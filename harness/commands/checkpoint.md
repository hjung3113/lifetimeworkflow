# /checkpoint — persist the volatile plane + commit

Captures a session checkpoint so work survives the ephemeral container (the derived `.memory/`
plane is regenerated on SessionStart, but `.memory/state/` is **committed** and must be saved
deliberately here).

## Steps

1. If an active task packet exists, first ensure its task/state/evidence/artifact revision is already
   committed and `state.current_ref` is that `HEAD`. Generate the HANDOFF, then write only its task
   ID/revision/path pointer to `.memory/state/active-task.json`;
   never copy packet, evidence, artifact, contract, or log bodies into `.memory/state/`.

   !`uv run python -m tools.handoff generate .workflow/tasks/<task-id> && uv run python -m tools.handoff validate .workflow/tasks/<task-id> && uv run python -m tools.handoff activate .workflow/tasks/<task-id> --state-dir .memory/state`

2. Update the committed state files with the current focus and progress:
   - Write `updated: "YYYY-MM-DD"` in YAML frontmatter on **every** checkpoint for both
     `.memory/state/activeContext.md` and `.memory/state/progress.md`. The date must be quoted so
     it round-trips as a string rather than a YAML date object.
   - `.memory/state/activeContext.md` — what is in flight right now and what is next.
   - `.memory/state/progress.md` — a short last-N-done summary under `## Recently done (last 5)`
     plus what remains under `## Remaining`.
   - The done summary is bounded, never append-only: drop older entries rather than accumulating a
     growing done-log. **git holds the full completed history**.

   These are the **committed** state plane (survive the container); the `derived/` plane is
   gitignored and regenerated by `python -m tools.memory_regen.inject` on SessionStart — do NOT
   hand-edit derived files here.

3. Stage **only** the state-plane files and the generated HANDOFF (never `git add -A`) and commit.
   This commit is the publication trust root: it contains the exact HANDOFF/pointer bytes and its
   parent is `state.current_ref`. When an active task pointer was updated, add both files explicitly:

   !`git add .memory/state/activeContext.md .memory/state/progress.md`

   !`git add .memory/state/active-task.json` (only when it exists and was updated)

   !`git add .workflow/tasks/<task-id>/handoffs/revision-<n>.json` (only when an active task exists)

   !`git commit -m "checkpoint: publish volatile state and handoff" .memory/state/activeContext.md .memory/state/progress.md [and active-task.json + HANDOFF when present] && uv run python -m tools.handoff validate .workflow/tasks/<task-id>`

## Notes

- Only the committed `state/` plane is checkpointed; derived memory stays gitignored.
- Stage files individually — this command never blanket-adds the working tree.
- Memory is not a changelog: durable decisions belong in append-only `docs/adr/`, completed history
  belongs in git, and `.memory/state/` stays tight.
- A checkpoint remains optional; when there is no active task, preserve the existing two-file flow.
