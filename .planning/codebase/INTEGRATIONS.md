# External Integrations

**Analysis Date:** 2026-07-14

## Scope Note

This document covers integration surfaces of the **harness core** (`tools/**`, `harness/**`, `libs/**`, `contracts/**`, `.github/workflows/*.yml`). The `.opencode/` and `.claude/` trees are generated *targets* of the emit pipeline, not integrations themselves. `examples/log-parser/` is a reference instance that adds a .NET toy converter as a CLI-spawn integration point — mentioned here only where the core wires to it (CI matrix, golden runner).

## Runtime Hosts (agent harness targets)

**opencode (primary target):**
- Config: `opencode.json` (repo root) — formatter commands, `instructions` pointers, 15-key permission matrix, registered plugin list
- Plugin: `harness/plugins/session-inject.ts` is the one plugin currently wired into `opencode.json`'s `plugin` array; `contract-guard.ts`, `format-on-write.ts`, `polyglot-lint.ts`, `secret-scan.ts` exist as **authored-but-unwired** adapters (see below)
- Status: **execution-deferred** — there is no opencode runtime installed in this container. All `harness/plugins/*.ts` files carry a "RESUME NOTE — AUTHORED-ONLY, EXECUTION DEFERRED" comment block; hook names (`tool.execute.before/after`, `chat.system.transform` vs `experimental.chat.system.transform`, `event` session.created) are flagged MEDIUM-confidence and must be re-verified against the live opencode API before wiring/testing
- Emitted output tree: `.opencode/**` (generated by `tools/harness_emit`, not source)

**Claude Code (secondary/dev target):**
- Emitted output tree: `.claude/{agents,commands,skills}` + `.claude/settings.json` (generated by `tools/harness_emit`)
- `.claude/package.json` — `{"type": "commonjs"}` only; no dependency manifest
- Native hook surface (PreToolUse/PostToolUse/Stop) is the **live** counterpart each opencode `.ts` plugin stub mirrors: `harness/plugins/contract-guard.ts` ↔ `python -m tools.hooks.contract_guard`, `format-on-write.ts` ↔ `tools.hooks.format_on_write`, `polyglot-lint.ts` ↔ `tools.polyglot_lint.lint`, `secret-scan.ts` ↔ `tools.hooks.secret_scan`, `session-inject.ts` ↔ `tools.memory_regen.inject`
- All five `tools/hooks` / gate Python modules run under `uv run python -m ...`, invoked via `execFileSync` (argv form, no shell string) from the TS stubs — deliberate command-injection defense

## CLI-Spawn / Process Integrations

**Language boundary rule:** cross-language calls happen only via process spawn + file/DB — never in-process object passing (A-model, restated in `AGENTS.md` non-negotiable #2).

- `tools/golden_runner` spawns the .NET toy converter (`examples/log-parser` instance) over the CLI boundary, captures its `--out` file, normalizes both sides via `libs/python/normalize`, diffs against the approved `.verified` baseline
- `tools/bootstrap/install.sh` shells out to `curl -fsSL https://dot.net/v1/dotnet-install.sh` (HTTPS-only, no untrusted-input interpolation) to install .NET 10 SDK, and to `uv sync --all-packages` for the Python workspace — runs idempotently on every SessionStart
- `harness/git-hooks/pre-commit` (source-controlled, not auto-installed into `.git/hooks`) execs `uv run python -m tools.hooks.commit_gate`, which composes contract-drift + polyglot §4.3-4.6 lint + golden-parity (golden-parity SKIPs-with-log when .NET is absent, never silently passes)

## Contract Validation

**JSON Schema (Draft 2020-12):**
- `contracts/**/*.schema.json` is the single source of truth (`contracts/normalization/format-conventions.schema.json`, `contracts/sample/greeting.schema.json`)
- Validated via `jsonschema` 4.26.0 (Python library, used by `tools/harness_lint`) and `check-jsonschema` 0.37.4 (CLI, used by CI's `contract-check` job and the `/contract-check` command)
- CI (`contract-check` job in `.github/workflows/ci.yml`) globs `contracts/**/*.schema.json` **and** `examples/**/contracts/**/*.schema.json`, pairing each schema with a sibling `.yaml`/`.yml`/`.json` instance; presence-safe (visible SKIP if zero pairs found, never a silent no-op pass)

**Schema-hash drift gate (RFC 8785 / JCS):**
- `tools/contract_hash` — canonicalizes each schema via `rfc8785` 0.1.4, SHA-256 hashes it, writes `contracts/.hashes/manifest.json` (committed baseline)
- `tools/contract_drift` — recomputes live hashes and diffs against the committed baseline; classifies breaking vs non-breaking changes; trips CI's `drift` job on any unapproved change
- Gates both the root manifest and the example manifest (`examples/log-parser/contracts/.hashes/manifest.json`) with the same CLI, no re-implementation
- Also has a `--workspace` mode for the cross-repo `workspace.toml` manifest (see Multi-Repo Workspace below)

## Data Storage

**Databases:** None — no database client or connection code found in the harness core.

**File Storage:** Local filesystem only. Constitution-plane artifacts (`contracts/`, `golden/`, `docs/adr/`) and derived-plane artifacts (`.memory/derived/`) are plain files under version control (constitution plane) or gitignored-and-regenerated (derived plane).

**Caching:** None external — `tools/memory_regen` intends on-disk tree-sitter tag caching (per `CLAUDE.md` stack guidance) but no explicit cache implementation was found in this pass beyond the gitignored `.memory/derived/` regeneration targets.

## Authentication & Identity

None — no auth provider, API keys, or identity integration in the harness core. `harness/permission-matrix.json` governs **agent tool permissions** (opencode's 15-key matrix: `bash` last-wins glob scopes, `path_deny_globs` for `contracts/**`, `docs/adr/**`, `golden/**`, `*.env`), not user authentication.

## Monitoring & Observability

**Error Tracking:** None.

**Logs:** No structured logging framework; tooling emits plain stdout/stderr (e.g. `tools/bootstrap/install.sh` echoes `[bootstrap] ...` lines; CI job `stale-derived` echoes remediation instructions on failure).

## CI/CD

**Hosting:** GitHub Actions (`.github/workflows/ci.yml`), `ubuntu-latest` runners, triggered `on: pull_request`. Top-level `permissions: { contents: read }` (least-privilege). No `${{ github.event.* }}` interpolation into any `run:` shell (matrix legs derive only from repo-owned `harness/project.toml`).

**Actions used (all pinned, official publishers):**
- `actions/checkout@v7.0.0`
- `astral-sh/setup-uv@v8.3.2`
- `actions/setup-dotnet@v5.4.0` (`dotnet-version: '10.0.100'`, dotnet leg + golden job only)

**Jobs (fan into a single `gate` job — the one enabled as a required branch-protection status check):**
| Job | Purpose |
|-----|---------|
| `setup` | Emits the per-language test matrix from `harness/project.toml` via `tools.harness_config.loader.languages()` — config-derived, not hardcoded |
| `lang-tests` | Fans out one leg per configured language (dotnet + python for the log-parser instance) |
| `contract-check` | `check-jsonschema` over `contracts/**` + `examples/**/contracts/**` schema/instance pairs |
| `drift` | `python -m tools.contract_drift.drift` against root manifest + example manifest |
| `golden` | `pytest tools/golden_runner` (converter-agnostic identity golden) + `pytest examples/log-parser/tests` (.NET parity, real .NET install) |
| `core-suite` | `uv run pytest` — the harness's own suite (`tools/` + `libs/python`), including GEN-03/GEN-04 config-consistency guards |
| `emit-drift` | Re-runs `tools.harness_emit`, fails on any diff in `.opencode`, `opencode.json`, `.claude/{agents,commands,skills,settings.json}`, `AGENTS.md`, `CLAUDE.md` — the single-source dual-runtime drift gate |
| `stale-derived` | Regenerates `docs/reference/**` (`tools.docs_sync`) and `.memory/derived/contracts-index.md` (`tools.memory_regen.contracts_index`); fails on any diff (uses `git add -A` + `git diff --cached` to catch newly-created pages) |
| `workspace` | Cross-repo (`workspace.toml`) drift + consistency gates (`tools.contract_drift.drift --workspace`, `tools/workspace_config`, `tools/harness_lint` workspace tests, workspace golden/drift tests) |
| `gate` | Fan-in; `if: always()`; fails if any upstream job failed/cancelled |

**Enforcement caveat:** the `gate` job is only truly non-bypassable once a human enables it as a required status check in GitHub branch protection settings — this is explicitly out of scope for the workflow file itself (a repo-setting action, not code).

## Repo-Map / Derived-Memory Generation

- `tools/memory_regen/repo_map.py` uses `tree-sitter` 0.25.2 + language grammars (`tree-sitter-python` 0.25.0, `tree-sitter-c-sharp` 0.23.5, `tree-sitter-bash` 0.25.1) to parse source into symbol defs/refs, then `networkx` 3.6.1 for personalized PageRank ranking → writes `.memory/derived/repo-map.md` (gitignored, regenerated)
- `tools/memory_regen/contracts_index.py` regenerates `.memory/derived/contracts-index.md` from the contract-hash/drift modules
- `tools/memory_regen/inject.py::assemble()` is the **single injection contract** consumed identically by both runtimes: the opencode `session-inject.ts` plugin (`event` hook, deferred) and the native Claude Code `SessionStart` hook — same ~1k-token-capped, banner-first, priority-truncated, pointer-only payload

## Webhooks & Callbacks

**Incoming:** None.

**Outgoing:** None — the only outbound network call in the harness core is `tools/bootstrap/install.sh`'s HTTPS fetch of the official .NET install script from `dot.net`.

## Multi-Repo Workspace (MREPO)

- `workspace.toml` (repo root) declares a workspace one level above `harness/project.toml`: member repos (`[[members]]`, e.g. `member-a`, `member-b` — generic default fixtures under `tests/fixtures/workspace/`) and cross-repo pipeline edges (`[pipeline].edges`, `repo:stage` endpoint syntax)
- `tools/workspace_config` — stdlib `tomllib` loader (`load_workspace()`, `members()`, `edges()`, `split_endpoint()` helper), zero external deps
- Consistency enforced by `tools/harness_lint/tests/test_workspace_config.py` (every edge's endpoints must name a declared member; every edge contract must resolve in its producer member's tree)
- CI `workspace` job runs the cross-repo drift + golden + consistency test set (see CI table above)

## Environment Configuration

**Required env vars:** None required by the harness core's own tooling beyond standard `PATH`/`DOTNET_ROOT` (`DOTNET_ROOT` defaults to `$HOME/.dotnet` in `tools/bootstrap/install.sh`).

**Secrets location:** None found/expected. `harness/permission-matrix.json` explicitly denies agent write access to `*.env` / `**/*.env` paths, and `tools/hooks/secret_scan.py` (mirrored by `harness/plugins/secret-scan.ts`) provides a shape-anchored content secret scanner as a PreToolUse gate.
