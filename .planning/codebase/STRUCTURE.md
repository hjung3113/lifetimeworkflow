# Codebase Structure

**Analysis Date:** 2026-07-14

This structure covers the **harness core** (`tools/`, `harness/`, `libs/`, `contracts/`, `docs/`,
`.github/workflows/`). `examples/log-parser/` is a reference instance — secondary, and mirrors much
of this same shape one level down (its own `agents/`, `contracts/`, `golden/`, `skills/`, `tests/`).
`.opencode/` and `.claude/` are **generated output**, never source — do not add code there by hand.

## Directory Purposes

**`harness/`:**
- Purpose: The runtime-neutral authored source the emitter reads. Editing an agent, command,
  skill, plugin, or permission means editing here — never `.opencode/` or `.claude/` directly.
- Contains: Markdown with YAML frontmatter (agents/commands/skills), `.ts` plugin sources (copied
  verbatim, never parsed by the emitter), JSON/TOML config.
- Key files: `harness/project.toml` (language/instance/topology SSOT),
  `harness/permission-matrix.json` (access-control SSOT), `harness/agents/orchestrator.md`
  (primary-mode entry-point persona).

**`tools/`:**
- Purpose: The reusable Python engine — every gate, generator, and hook the harness runs. Each
  subdirectory is an independent uv workspace member (own `pyproject.toml`, own `tests/`).
- Contains: `__init__.py` + `__main__.py` (where CLI-invocable) + implementation module(s) +
  `tests/` subdir per member. Members are declared in the root `pyproject.toml`
  `[tool.uv.workspace] members = ["libs/python", "tools/*"]` (excluding `tools/bootstrap`, which is
  shell-only).
- Key files: `tools/harness_emit/generate.py` (emit spine),
  `tools/contract_drift/drift.py` (drift gate), `tools/golden_runner/runner.py` (golden loop),
  `tools/harness_lint/tests/test_core_no_example_dep.py` (GEN-04/05 guard).

**`libs/`:**
- Purpose: Language-neutral shared code that stays in the core regardless of which instance is
  active — the §4.3–4.6 canonicalization engine and its spec/fixtures.
- Contains: `libs/python/normalize/core.py` (the one Python implementation of BOM/CRLF/decimal/
  timezone/null/TSV canonicalization), `libs/normalize-spec.md` (the rule-of-record prose spec),
  `libs/normalize-fixtures/*.json` (shared (raw, canonical) corpus both languages validate against).
- Key files: `libs/python/normalize/core.py`, `libs/python/AGENTS.md` (per-package rules), `libs/
  normalize-spec.md`.

**`contracts/`:**
- Purpose: Constitution plane, root/generic-default instance. Single source of truth for data
  shape; human-owned, CODEOWNERS-gated (agents never write here directly per root `AGENTS.md`).
- Contains: `.schema.json` (JSON Schema Draft 2020-12, the validated/hashed artifact) + sibling
  YAML instance data; `.hashes/manifest.json` is the committed drift-gate baseline.
- Key files: `contracts/normalization/format-conventions.schema.json` (§4-5 materialized
  convention contract — included in the drift manifest so a convention flip is caught, not just
  column changes), `contracts/README.md` (Korean-language plane declaration + seed-placeholder
  disclaimer).

**`golden/`:**
- Purpose: Constitution plane — approved cross-language equivalence baselines. A top-level sibling
  of `contracts/`, not nested under it.
- Contains: One directory per case (`golden/<case>/`), each with `input/seed.tsv`,
  `expected/baseline.verified.tsv` (human-approved, never machine-written), and optionally
  `expected/baseline.received.tsv` (machine-proposed on FAIL) and `meta.yaml`.
- Key files: `golden/sample/expected/baseline.verified.tsv`.

**`docs/`:**
- Purpose: Diátaxis-structured documentation. `docs/adr/` and `docs/glossary.md` are constitution
  plane (human-owned); `docs/reference/` is committed-derived (machine-regenerated from
  `contracts/**`, CI-verified fresh by the `stale-derived` job).
- Contains: `docs/adr/000N-<slug>.md` (append-only, supersede-never-edit), `docs/explanation/`,
  `docs/how-to/`, `docs/tutorials/` (currently placeholder stubs), `docs/reference/*.md`.
- Key files: `docs/adr/0002-general-template-de-specialization.md` (defines the template↔instance
  split), `docs/glossary.md`.

**`.memory/`:**
- Purpose: The two-plane (three-tier) context-memory root. Declares and holds the derived/state
  planes; the constitution plane lives elsewhere (`contracts/`, `docs/adr/`, `golden/`).
- Contains: `.memory/derived/repo-map.md` (gitignored, regenerated every session by
  `tools/memory_regen/repo_map.py`), `.memory/derived/contracts-index.md` (committed-derived,
  CI-verified), `.memory/state/{activeContext,progress}.md` (committed, agent-authored,
  provisional).
- Key files: `.memory/README.md` (the plane-declaration table — hand-authored, not itself
  derived).

**`examples/log-parser/`:**
- Purpose: The reference instance — a concrete semiconductor-equipment-log domain seed proving the
  core harness end-to-end. Secondary to the core; never a dependency of it.
- Contains: Its own `agents/`, `components/toy-converter` (.NET), `contracts/`, `golden/`,
  `libs/dotnet` (the .NET-side normalize twin), `skills/`, `tests/`, and `project.toml` (the
  instance's topology overlay).
- Key files: `examples/log-parser/AGENTS.md` (per-instance rules), `examples/log-parser/README.md`.

**`.opencode/` / `.claude/` (GENERATED — do not treat as source):**
- Purpose: Runtime-native artifact trees actually loaded by opencode (primary target) and Claude
  Code (secondary/dev environment). Entirely produced by `tools/harness_emit`.
- Contains: `.opencode/{agent,command,skill,plugin}/`, root `opencode.json`,
  `.claude/{agents,commands,skills}/`, `.claude/settings.json` (harness hook groups
  signature-merged in).
- Generated: Yes. Committed: Yes (so CI's `emit-drift` job can diff regenerate-vs-committed).
  Every file's first frontmatter line carries a DERIVED marker comment.

## Key File Locations

**Entry Points:**
- `python -m tools.harness_emit`: emit harness/ source to `.opencode/` + `.claude/`
  (`tools/harness_emit/__main__.py`).
- `python -m tools.contract_drift.drift [--workspace]`: contract-drift gate
  (`tools/contract_drift/drift.py`).
- `python -m tools.contract_hash.hash [--write]`: build/write the JCS-SHA256 baseline
  (`tools/contract_hash/hash.py`).
- `python -m tools.golden_runner.runner <case> [--out PATH]`: run one golden case
  (`tools/golden_runner/runner.py`).
- `python -m tools.golden_runner.approve --approve --adr <id>`: promote a golden baseline
  (`tools/golden_runner/approve.py`).
- `python -m tools.memory_regen.repo_map` / `.contracts_index` / `.inject`: regenerate derived
  memory (`tools/memory_regen/`).
- `python -m tools.docs_sync`: regenerate `docs/reference/**` from `contracts/**`
  (`tools/docs_sync/__main__.py`).
- `bash tools/contract_drift/check.sh`: shell wrapper for the drift gate.
- `bash tools/bootstrap/install.sh` / `verify.sh`: toolchain bootstrap (SessionStart).

**Configuration:**
- `harness/project.toml`: language/instance/pipeline-topology SSOT (GEN-03).
- `workspace.toml`: multi-repo member/edge SSOT (MREPO-01).
- `harness/permission-matrix.json`: access-control SSOT (CONFIG-02).
- `pyproject.toml` (root): uv workspace members/exclude, pytest/ruff/pyright config.
- `.github/workflows/ci.yml`: the single CI workflow (9 jobs, config-derived language matrix).

**Core Logic:**
- `tools/harness_emit/generate.py`: the emit spine (`emit()`, `main()`).
- `tools/contract_drift/drift.py`: `run_gate`, `classify`, `workspace_drift`.
- `tools/golden_runner/runner.py`: `run_golden_case`, `compare`, `run_converter`.
- `libs/python/normalize/core.py`: the §4.3–4.6 canonicalization engine (`normalize_tsv`,
  `normalize_cell`).
- `tools/harness_perms/resolver.py`: `resolve_bash`, `resolve_path` (pure permission logic).

**Testing:**
- Each `tools/<member>/tests/` directory: unit tests for that member, run via `uv run pytest`
  (root `pyproject.toml` `testpaths = ["libs/python", "tools"]`).
- `tools/harness_lint/tests/test_core_no_example_dep.py`: GEN-04/GEN-05 core→example guard.
- `tools/harness_lint/tests/test_language_config.py`, `test_pipeline_config.py`,
  `test_workspace_config.py`: config-consistency gates.
- `examples/log-parser/tests/`: instance-level tests (kept OFF root `testpaths`; CI targets it
  explicitly).

## Naming Conventions

**Files:**
- Python tool modules: `snake_case.py`, one primary module per concern (e.g. `drift.py`,
  `runner.py`, `resolver.py`) inside a `snake_case` package dir matching the tool's SCREAMING-CASE
  task id lowercased (e.g. `contract_drift` ← CONTRACT-04).
- Authored Markdown artifacts: `kebab-case.md` (`harness/agents/code-reviewer.md`,
  `harness/commands/golden-approve.md`, `harness/skills/two-plane-memory/SKILL.md` — note the
  skill's file itself is always literally `SKILL.md` inside a `kebab-case` directory).
- JSON Schema contracts: `<name>.schema.json` with an optional sibling `<name>.yaml`/`.yml`/`.json`
  instance (`contracts/sample/greeting.schema.json`).
- ADRs: `docs/adr/NNNN-kebab-slug.md`, zero-padded 4-digit sequence, append-only.
- Golden cases: `golden/<case-slug>/{input/seed.tsv, expected/baseline.verified.tsv,
  expected/baseline.received.tsv, meta.yaml}`.

**Directories:**
- `tools/<snake_case_tool_name>/` — one uv workspace member per gate/generator, always containing
  its own `pyproject.toml` + `tests/`.
- `harness/<artifact_type>/` — flat, one directory per artifact kind (`agents/`, `commands/`,
  `skills/`, `plugins/`); `skills/` further nests one directory per skill (`skills/<skill-name>/`).
- `examples/<instance-name>/` — one directory per instance, mirroring the core's own top-level
  shape (`agents/`, `contracts/`, `golden/`, `libs/`, `skills/`, `tests/`).

## Where to Add New Code

**New harness agent/command/skill:**
- Author under `harness/agents/<name>.md`, `harness/commands/<name>.md`, or
  `harness/skills/<name>/SKILL.md` (+ `references/` if needed) — NEVER directly under `.opencode/`
  or `.claude/`.
- After authoring: run `python -m tools.harness_emit` to project both runtime trees, then commit
  BOTH the `harness/` source and the regenerated `.opencode/`/`.claude/` output (the `emit-drift`
  CI job requires them to match).
- A new skill must also be added to `EXPECTED_SKILLS`/whatever anti-drift set
  `tools/harness_emit/validate.py::check_skill_set` enforces, or emit will fail loud.

**New gate/generator tool:**
- Create `tools/<snake_case_name>/` with its own `pyproject.toml`, `__init__.py`, an implementation
  module, and a `tests/` subdir — this auto-joins the uv workspace via the root
  `[tool.uv.workspace] members = ["libs/python", "tools/*"]` glob.
- If it needs the shared normalization core, use the `sys.path` shim pattern from
  `tools/golden_runner/runner.py:28-34` (insert `libs/python` before importing `normalize.core`) —
  never reimplement §4.3–4.6 logic locally.
- Wire it into `.github/workflows/ci.yml` as a new job (or a step in an existing job) if it should
  gate merges.

**New contract:**
- Add `<name>.schema.json` (+ optional instance YAML) under `contracts/<category>/` (root instance)
  or `examples/<instance>/contracts/<category>/` (instance-specific). Rebaseline with
  `python -m tools.contract_hash.hash --write` and pair the change with a golden/ADR update — this
  is CODEOWNERS-gated, not an agent-autonomous edit.

**New golden case:**
- Add `golden/<case-slug>/input/seed.tsv` + a human-approved
  `golden/<case-slug>/expected/baseline.verified.tsv` (never machine-generated for a NEW case —
  promotion via `/golden-approve` only for cases that already ran and produced a `.received.tsv`).

**New instance (fork/clone as a fresh domain):**
- Add `examples/<new-instance>/` mirroring `examples/log-parser/`'s shape (own `agents/`,
  `contracts/`, `golden/`, `libs/`, `skills/`, `tests/`, `project.toml`).
- Point `harness/project.toml [instance] root` and the per-language `persona`/`test_paths` fields
  at the new instance (the ONE sanctioned core-plane place allowed to name an instance path — see
  `tools/harness_lint/tests/test_core_no_example_dep.py`'s `_INSTANCE_ROOT_FILE` exemption).
- Never add an `examples/` path reference anywhere else under `tools/`, `harness/`, or `libs/` — the
  GEN-04 guard will fail the suite.

**New workspace member (multi-repo):**
- Add a `[[members]]` entry to `workspace.toml` (`id`, `root` — must stay inside `REPO_ROOT`), and
  any cross-repo `[pipeline].edges` it participates in. Give it its own `contracts/.hashes/
  manifest.json` baseline before declaring it, or `workspace_drift` reports a
  `missing-baseline` failure.

**Utilities:**
- Shared, language-neutral helpers belong in `libs/python/` (only if they are part of the
  §4.3–4.6 canonicalization concern) or as a new `tools/<name>/` member (for a new gate/generator
  concern). There is no generic catch-all `utils/` directory — every `tools/` member is scoped to
  one named concern.

## Special Directories

**`.opencode/` / `.claude/`:**
- Purpose: Generated runtime-native artifact trees.
- Generated: Yes (by `tools/harness_emit`).
- Committed: Yes — committed specifically so CI's `emit-drift` job can diff a fresh regenerate
  against them and fail on any hand-edit or stale commit.

**`.memory/derived/`:**
- Purpose: Repo-map + (tracked exception) contracts-index derived artifacts.
- Generated: Yes (`tools/memory_regen`).
- Committed: `repo-map.md` is gitignored (regenerated every session); `contracts-index.md` is
  committed and CI-verified fresh by the `stale-derived` job.

**`docs/reference/`:**
- Purpose: Rendered reference docs derived from `contracts/**`.
- Generated: Yes (`tools/docs_sync`).
- Committed: Yes, CI-verified fresh by the `stale-derived` job (same job as
  `.memory/derived/contracts-index.md`).

**`.pytest_cache/`, `.ruff_cache/`, `**/__pycache__/`, `.venv/`:**
- Purpose: Standard Python tool caches / virtualenv.
- Generated: Yes. Committed: No (gitignored).

**`contracts/.hashes/`:**
- Purpose: The committed JCS-SHA256 drift-gate baseline manifest.
- Generated: Yes (`tools/contract_hash --write`), but treated as constitution-plane-adjacent —
  changing it is the deliberate "rebaseline" act that must be paired with a golden/ADR update.
- Committed: Yes.
