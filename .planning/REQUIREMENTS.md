# Requirements: v2.6 Minimal Monorepo Core

**Defined:** 2026-07-30
**Milestone:** v2.6 Minimal Monorepo Core (phases 47, 48, 49, 50a, 50b)
**Core Value:** 계약(contracts)을 단일 정본으로 두고, 폴리글랏 표현차·전환 리스크를 하네스가 자동으로
강제·검증한다 — 그리고 이 강제 구조가 특정 도메인·언어에 묶이지 않고 어느 프로젝트에나 재사용된다.

**Milestone goal:** close gap ③ of the owner's four-part purpose — *an LLM working in this repo
understands cross-project relationships better than it would in a generic repo*. ①②④ are already
covered by shipped artifacts (lint adapters + nearest-wins `AGENTS.md` + `/component`; `contracts/` +
`contract_hash`/`contract_drift` + `contract_graph` + CI; append-only ADR + derived plane +
ADR-0011's CI-strong posture).

**Binding constraint (carried from v2.5, governs every requirement below):** 목적 이상으로 불필요한
검증 게이트나 보안으로 규모를 확장하지 말 것. Default answer to "should we also gate X?" is **NO**.
The surface may not grow without retiring at least as much. Where a requirement below adds surface,
it names what it retires.

## v2.6 Requirements

### Package Facts (Phase 47)

- [x] **MONO-01**: An agent can read one committed **derived** package graph that lists every package
  in the monorepo with its manifest path, language, and package id — regenerated by a generator under
  `tools/`, never hand-edited, byte-identical on regeneration.
- [x] **MONO-02**: Package dependency edges are **derived from the manifests themselves**
  (`pyproject.toml`, `package.json`, `go.mod`, `Cargo.toml`, `*.csproj`) by extending
  `tools/adoption_scan/detect.py`'s existing `detect_manifests` (`:41-47,100-121`), which today
  records manifest existence but parses no dependencies. No hand-maintained dependency list.
- [x] **MONO-03**: `[[components]]` in `harness/project.toml` becomes an **override slot** layered
  over the derived facts — a declared component overrides the derived record for the same package,
  and every existing config (core + `examples/log-parser/`) stays valid with no edit.
- [x] **MONO-04**: The package graph feeds `contract_graph` so a contract can be attributed to the
  package that owns it. **Report-only: this phase adds no gate and no CI job.**

### Convention Profiles (Phase 48)

- [x] **MONO-05**: An agent working in any package can ask which conventions apply there and get the
  **nearest-wins** answer — the nearest enclosing package's profile, not the repo-wide default.
- [x] **MONO-06**: Each language's lint and test commands are derived from the existing
  `[[languages]]` slot in `harness/project.toml`, so a convention profile never restates a command
  that the language config already owns.
- [ ] **MONO-07**: `/component` step 2 populates a convention profile for the new package as part of
  its existing mandated order (structure → AGENTS.md → tests), adding **no new command**.

### Contract Impact (Phase 49)

- [ ] **MONO-08**: A developer can run `/impact <contract>` and see which contracts and which
  **packages** are affected, built on `contract_graph.query`'s existing `direct`/`reverse`/
  `transitive` (`query.py:29,39,55`) plus the Phase-47 package facts — no second traversal engine.
- [ ] **MONO-09**: `/impact` runs **on demand only** — no SessionStart injection, no gate, no CI job.
  It fills phase 46's evidence slot in the `contract-change` route.

### Harness Authoring (Phase 50a)

- [ ] **MONO-10**: A developer can author a new harness artifact through a `harness-author` skill
  that asks grounded questions and offers defaults cited as `path:line` from this checkout, writing
  its output **runtime-neutral under `harness/` only** (the emitter projects it).
- [ ] **MONO-11**: `harness-author` **absorbs `skill-creator`**, keeping the skill count net ±0
  (8 → 8), and adds zero new packages, commands, or contracts.

### Managed Adopt / Upgrade (Phase 50b)

- [ ] **MONO-12**: `/adopt` becomes a managed install/update over one manifest, reporting conflicts
  rather than silently overwriting a target repo's files. **Blocked precondition:** a real
  multi-package target repo. If none exists when the phase is reached, 50b blocks and is carried —
  it does not stall the milestone, and 50a ships independently.

## Deferred to a Later Milestone

- **EVOL-02** — contract versioning / compatibility engine. Still a standalone engine needing its
  own ADR; unchanged since v2.4.
- **D-24** — CODEOWNERS advisory on this repo, re-openable as a machine-side check on golden
  baseline diffs. Now unblocked by ADR-0012, but adding a gate contradicts this milestone's
  no-growth constraint unless something retires with it. Stays a documented residual.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Any gate proving the harness cannot bypass itself | Retired by ADR-0012 — CI and the merge are the decision authority. Re-adding one reverses a ratified decision. |
| Any security control not motivated by a threat this repo faces | v2.5 binding constraint; the bash surface is a permanent residual by design (ADR-0012). |
| Any human-must-**author** step | v2.5 reduced these 5 kinds → 0. The human's only act is reviewing and merging a PR. |
| SessionStart injection of package facts or impact results | MONO-09 is explicit: on demand only. The injector has a ~4,000-char budget and a pointer-only contract. |
| A second graph/traversal engine | MONO-08 reuses `contract_graph.query`. The harness forbids a second authority plane. |
| Hand-maintained package or dependency lists | MONO-02: derived from manifests. Derived-plane artifacts are never hand-edited. |
| A CI gate on the derived package graph | MONO-04: report-only. The existing `stale-derived` job already covers derived freshness. |
| Autonomous contract extraction from a target repo | Carried out of v2.3 and still out — adoption proposes, humans decide. |
