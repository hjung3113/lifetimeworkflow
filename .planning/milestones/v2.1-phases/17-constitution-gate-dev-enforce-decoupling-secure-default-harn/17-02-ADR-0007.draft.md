# 7. Constitution-Gate Dev/Enforce Decoupling (Secure-Default HARNESS_DEV_BYPASS)

*MADR 4.x · plane: constitution (human-owned, immutable, append-only)*

- **Status:** accepted
- **Date:** 2026-07-15
- **Deciders:** operator-delegated, from the approved brainstorm spec (`docs/superpowers/specs/2026-07-14-contract-guard-dev-bypass-design.md`)
- **Supersedes:** —
- **Superseded by:** —
- **Complements:** [ADR-0004](0004-constitution-hook-fail-open-posture.md) (constitution-plane hook posture) — this ADR adds a secure-default, explicitly-opt-in dev bypass to the same `contract_guard` gate without changing its fail-open-on-malformed-stdin behavior.

## Context and Problem Statement

The harness's own product guard `contract_guard` (HOOK-04) is wired as a live `PreToolUse(Write|Edit)`
hook in the **Claude dev session used to develop the harness** (`.claude/settings.json`), and
`commit_gate` gates `git commit` the same way. So the artifact-under-construction governs its own
workshop: an agent doing legitimate GSD work on the harness's own `docs/adr/` / `contracts/` /
`golden/` is denied (verified live when an agent Write to `docs/adr/0006-*.md` was correctly refused
during Phase 12), and a bug in the WIP guard could brick all dev writes.

This is deliberate dogfooding — "an agent Write to `docs/adr/` is DENIED without the token" is a
verified behavior the harness must keep. But there was **no way for the dev human to opt the local
dev session out** without either disabling the dogfood entirely or fabricating the
`GOLDEN_APPROVE_HUMAN` audit token (which agents must never do).

## Decision Drivers

- **Secure by default.** The gates must stay enforce-by-default everywhere; only an explicit, local,
  human-set signal may relax them. A default-off enforcement (fail-open) is unacceptable.
- **Don't forge the audit token.** A dev bypass must be a *distinct* signal from
  `GOLDEN_APPROVE_HUMAN`, so a dev-bypassed write is never recorded as "human ratified".
- **The real gate is elsewhere.** CODEOWNERS review at PR merge is the non-bypassable ratification;
  the runtime hooks are accident-prevention, not a sandbox against a determined agent.
- **No runtime divergence.** Both emitted runtimes must keep identical guard code; the opt-out is a
  runtime env signal, not committed config.

## Considered Options

1. **Keep it fully entangled (status quo).** *Rejected:* the WIP product keeps bricking legitimate
   dev work and blocks in-session GSD execution.
2. **Enforce only when a flag is SET (`HARNESS_ENFORCE=1`).** *Rejected:* default becomes
   *no enforcement* — a fail-open constitution gate if any runtime forgets the flag.
3. **Don't emit the guard into the Claude dev runtime at all.** *Rejected:* loses dev-side dogfood
   and diverges the two emitted runtimes.
4. **Secure-default dev opt-out `HARNESS_DEV_BYPASS` (chosen).** Enforce by default; a distinct,
   local, human-set flag opts the dev session out, byte-hygiene never waived.

## Decision Outcome

**Chosen: Option 4.**

**(a) Secure default.** `HARNESS_DEV_BYPASS` unset / empty / whitespace-only ⇒ **no bypass** (the
gates enforce). Mirrors the `GOLDEN_APPROVE_HUMAN` blank-rule exactly.

**(b) Distinct from the token.** `HARNESS_DEV_BYPASS` is a separate env var from
`GOLDEN_APPROVE_HUMAN`. A dev-bypassed constitution write emits a distinct dev-only note
(`contract_guard`: a stderr note naming `HARNESS_DEV_BYPASS` + CODEOWNERS; `commit_gate`: a
`WARN (dev)` distinct from the token's `WARN (ratified)`) — a dev bypass is never labeled "ratified".

**(c) Byte-hygiene never waived.** Even a dev-bypassed constitution write still fails the §4.3-4.6
BOM/CRLF `lint_bytes` check — byte-pristineness is mechanical correctness, not a ratification concern.

**(d) One shared helper.** A single `dev_bypassed()` in `tools/hooks/_stdin.py` is honored by
`contract_guard.main()` (waives only the access-control deny) and by `commit_gate.check_drift()`
(**DRIFT-ONLY** — polyglot/golden stay hard).

**(e) Flag location.** The flag lives ONLY in gitignored `.claude/settings.local.json`; it is never
written into committed `settings.json`, CI workflows, or opencode config. Both runtimes ship
identical guard code.

**(f) CODEOWNERS stays the real gate.** The runtime opt-out only affects the local session; the
PR-merge CODEOWNERS review remains the non-bypassable ratification for the constitution plane.

### Consequences

- **Good:** the dev human can work on the harness's own constitution plane in-session without
  forging a token or disabling the guard; SC4 (deny by default) still holds and is regression-tested.
- **Good:** a dev-bypassed write is auditably distinct from a human-ratified one; the token's meaning
  is preserved.
- **Neutral / accepted:** byte-hygiene and polyglot/golden are never relaxed by the dev flag, so a
  dev bypass cannot mask §4.3-4.6 or equivalence regressions.
- **Bad / accepted (agent-self-enabling risk):** an agent could write `HARNESS_DEV_BYPASS` into
  `.claude/settings.local.json` to enable its own bypass. This is accepted as the **same trust model**
  as an agent editing `.claude/settings.json` to drop the hook entirely — the guard is
  accident-prevention, not a sandbox. The real defense is unchanged: the PR diff is visible and
  CODEOWNERS reviews it at merge.
