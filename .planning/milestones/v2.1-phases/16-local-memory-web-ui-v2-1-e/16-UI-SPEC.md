# Phase 16 — UI Design Contract

> Visual and interaction contract for the **Local Memory Web UI** (MEM2-07). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a local developer-hygiene tool, not a product/marketing UI.** The design contract's precision is spent on **states and interactions** (empty list, active vs retired, unsaved edit, orphan-warning confirm, post-retire), NOT on brand. The stack is locked by CONTEXT.md **D-16-01**: Python stdlib `http.server` bound to `127.0.0.1` serving **one self-contained inlined HTML/JS page** — **zero dependencies, no framework, no CDN, no build step, no external fonts/assets, no network fetch from the page**. Every value below must be expressible in plain HTML + inline `<style>` + vanilla JS. "Local only" is literal: there is nothing to fetch.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — locked by D-16-01 (no framework, no CDN, no build). Single inlined HTML/JS page served by stdlib `http.server`. |
| Preset | not applicable |
| Component library | **none** — hand-authored semantic HTML (`<ul>`, `<button>`, `<textarea>`, `<dialog>`). No radix / base-ui. |
| Icon library | **none** — no icon CDN/font. Use Unicode text glyphs only where needed (e.g. `▸`/`▾` disclosure, `•` bullet, `↩` retire). Status is conveyed by **text badges**, never icon-only. |
| Font | **System font stack only** (no web fonts). UI: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`. Markdown bodies + `file:line` referrers: `ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace`. |

**shadcn gate:** Not applicable — this is not a React/Next.js/Vite project and D-16-01 forbids a component framework. Registry safety: not applicable (no registry, zero third-party blocks).

**Rationale note for planner/executor:** The page CSS lives in a single inline `<style>` block emitted from `tools/memory_ui/page.py`. Keep all tokens below as CSS custom properties (`:root { --space-md: 16px; … }`) so the contract is auditable in one place and the ui-auditor can diff implemented values against this table.

## Spacing Scale

Declared values (multiples of 4; 8-point base). A compact single-viewport tool does not need page-level 48/64 tokens — they are intentionally omitted.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge padding, gap between a label and its inline meta |
| sm | 8px | Compact stacking (list-row internal padding, gap between buttons) |
| md | 16px | Default element spacing (form field vertical rhythm, panel padding) |
| lg | 24px | Section padding, gap between the two-column list/detail panels |
| xl | 32px | Page outer margin / top header separation |

Exceptions:
- **Focus outline** uses a fixed 2px width (not a spacing token) — accessibility affordance, see Typography/Color focus rows.
- **Hairline borders** use 1px (structural, not spacing).
- Touch-target sizing is not a goal (desktop dev machine, mouse/keyboard); do not pad controls up to 44px. Standard button height ~32px (padding `sm` vertical, `md` horizontal).

---

## Typography

Exactly **4 sizes, 2 weights**. Body line-height 1.5, headings 1.2.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Meta / badge / `file:line` | 12px | 400 regular (badges 600) | 1.4 | Referrer lists, `updated:` stamp, status badges. Monospace for `file:line`. |
| Body | 14px | 400 regular | 1.5 | List rows, form labels, dialog copy. Markdown edit `<textarea>` uses **monospace** at 14px/1.5. |
| Item title | 18px | 600 semibold | 1.3 | Agreement title / state-file name in the detail panel. |
| Page heading | 22px | 600 semibold | 1.2 | Single app title bar ("Memory") + panel section headers step down to 18/600. |

Weights allowed: **400 (regular)** and **600 (semibold)** only. No light/medium/bold-800. Retired-item titles keep weight 600 but drop to the muted color + strike (see Color / States).

## Color

Restrained neutral palette, system-native, light scheme. 60/30/10 split. All values are plain hex usable inline; expose as CSS custom properties.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` surface / `#1a1a1a` text | Main detail panel background + primary body text |
| Secondary (30%) | `#f4f5f7` panel fill / `#e4e6ea` hairline borders / `#6b7280` muted text | List/sidebar column, form field backgrounds, dividers, meta text, **retired-item title color** |
| Accent (10%) | `#2563eb` | See reserved-for list below — nothing else |
| Destructive | `#b91c1c` | The **"Retire anyway"** confirm button (orphan dialog) + validation/error text only |

Accent reserved for (explicit — never "all interactive elements"):
1. The **primary action button** in a given view (`Save changes` on an edit; `Add agreement` on the add form) — one accent-filled button per view maximum.
2. The **selected list row** left-edge indicator (2px accent bar) + selected-row label.
3. The **keyboard focus ring** (`outline: 2px solid #2563eb; outline-offset: 2px`) on all interactive elements.

Secondary (non-primary) buttons — `Cancel`, `Edit`, `Retire` trigger — are neutral: `#ffffff` fill, `#e4e6ea` border, `#1a1a1a` text. They do **not** use accent.

Additional semantic tokens (support the load-bearing states; still within the restrained palette):

| Token | Value | Usage |
|-------|-------|-------|
| Warning surface | `#fff7ed` fill / `#c2410c` text / `#fdba74` border | The **orphan-warning banner + dialog header** (teaching surface). Amber = "stop and read", distinct from destructive red. |
| Active badge | `#e4e6ea` fill / `#374151` text | `ACTIVE` badge on agreements — neutral, not attention-grabbing. |
| Retired badge | `#6b7280` fill / `#ffffff` text | `RETIRED` badge — filled muted-gray; paired with strikethrough muted title. |
| Dirty / unsaved dot | `#c2410c` | 8px dot + "Unsaved changes" meta text on an edited-but-unsaved item. |

**Contrast:** all text/background pairs above meet WCAG AA (≥4.5:1 for body, ≥3:1 for 12px badges on their fills). Do not introduce lighter grays for body text.

**No dark mode in the contract.** A `@media (prefers-color-scheme: dark)` block is optional executor discretion but out of scope for verification; the light values above are the contract.

## Copywriting Contract

Tone: terse, factual, teaching. Mirror the harness's `REFUSED:` / `REVIEW:` voice (see `<specifics>`), not marketing. Name the item, count the referrers, list them as `file:line`.

| Element | Copy |
|---------|------|
| Primary CTA (edit view) | **Save changes** |
| Primary CTA (add-agreement view) | **Add agreement** |
| Retire trigger (neutral button, per agreement) | **Retire** |
| Empty state heading (agreements) | **No active agreements** |
| Empty state body (agreements) | This is expected. Agreements are captured only from explicit feedback via `/agree` — never authored by a tool. Retired agreements, if any, appear under **Show retired**. |
| Empty state (referrers panel) | **Nothing points to this item.** No `.memory/…` path or slug references were found in the scanned roots (`docs/`, `harness/`, `inject.py`, `.memory/README.md`, `AGENTS.md`). Retiring or renaming it will not orphan anything. |
| Error state — blank `--because` (write refused) | **Can't add: a reason is required.** The `Because` field explains why this agreement exists. Enter the reason from your own feedback — the tool will not invent one. |
| Error state — write refused (generic `AgreementRefused`) | **Refused.** `{verbatim REFUSED: message from tools.agree.write}`. Nothing was written. |
| Error state — stale-index warning | **Referrers below are from the last regen.** Run `/refresh-memory` (or reload) to rescan before relying on this list. |
| Progress save confirmation | **Saved.** `updated:` stamped `{date}`; body unchanged elsewhere. |
| Post-retire state | **Retired.** `{slug}` is now `status: retired` — kept, not deleted. It stays listed under **Show retired**. |
| Destructive confirmation — zero referrers | **Retire `{slug}`?** It will be marked `status: retired`, not deleted. → buttons: `Cancel` (default) / `Retire` |
| Destructive confirmation — N referrers (load-bearing) | **`{N}` references point to `{item}`.** Retiring it will orphan them. This tool will **not** rewrite those files — you must reconcile them by hand. Referrers:\n`{file}:{line}` × N (monospace list, `kind` shown as `path`/`slug`).\n→ buttons: `Cancel` (default focus) / `Retire anyway` (destructive) |

Unsaved-edit copy: **Unsaved changes** (with dirty dot); on navigate-away attempt: **Discard unsaved changes to `{item}`?** → `Keep editing` (default) / `Discard`.

## Interaction Contract (load-bearing — the real spec)

This section, not the palette, is what this phase must get right. Executor treats it as the visual source of truth; ui-auditor compares against it.

### Layout (single desktop viewport)
- Two-column: **left list panel** (secondary `#f4f5f7`, ~320px, fixed) + **right detail panel** (dominant `#ffffff`, fluid). App title bar spans the top.
- Left panel has two labeled groups: **Progress state** (`activeContext.md`, `progress.md` — always exactly these two) and **Agreements** (active by default; a **Show retired** toggle appends retired ones below a divider). No search/filter is required (the corpus is tiny).
- Right panel shows the selected item: title + badges + meta (`updated:` for state; `status`/`added`/`because` for agreements), a **Referrers** sub-panel ("What points to this"), and the body (rendered read view + an **Edit** affordance).
- Responsive/mobile is explicitly not a goal — do not add breakpoints beyond graceful narrow-window wrapping.

### The five states each item view must express

| State | Visual contract |
|-------|-----------------|
| **Empty list** (no active agreements — the legitimate default today) | Agreements group shows the empty-state copy (above), not a blank void. Progress-state group is never empty (two fixed files). |
| **Active agreement** | Neutral `ACTIVE` badge, title at 18/600 in `#1a1a1a`, body legible. Edit + Retire available. |
| **Retired agreement** | Filled-gray `RETIRED` badge, title strikethrough in muted `#6b7280`, body dimmed. **Hidden behind `Show retired` toggle** by default. Retire button is absent (already retired); Edit still allowed (body/reason). Never shown as deleted — it must be visibly present. |
| **Unsaved edit (dirty)** | Dirty dot (`#c2410c`) + "Unsaved changes" meta next to the title; `Save changes` becomes the accent primary button; navigating away triggers the discard confirm. |
| **Post-retire** | Item immediately re-renders in the Retired state (badge + strike), stays selected, shows the post-retire confirmation copy; list re-sorts it under the retired divider. |

### Referrers ("What points to this item") sub-panel
- Reads `.memory/derived/pointer-index.json` (DERIVED, read-only in the UI — never editable here).
- **Zero-referrer state:** show the empty-referrers copy (above) — a positive, reassuring "safe to retire" message, not an error.
- **N-referrer state:** a monospace list of `file:line` rows, each with its `kind` (`path` outranks `slug`) shown as a small trailing tag. Rows are read-only text (no auto-navigation, no rewrite affordance — surfacing only, per D-16-03).
- Label the panel's freshness: "from last regen" meta so a stale index is never mistaken for ground truth (Pitfall 4).

### Referential-integrity confirm — the single most important interaction (D-16-03)
Triggered on **retire**, or on an **edit that changes a slug/path**. Flow:
1. Before the destructive write, the server queries (ideally inline-regenerates) the pointer-index for the item.
2. **Zero referrers →** lightweight confirm (zero-referrer copy above): `Cancel` (default) / `Retire`. No amber, no red-heavy framing — it is a routine state flip.
3. **N referrers →** a modal `<dialog>` with the **warning surface** (amber header `#fff7ed`/`#c2410c`), the N-referrer copy, and the full `file:line` referrer list in monospace. Buttons: **`Cancel`** (neutral, **default keyboard focus**, `Esc` closes) and **`Retire anyway`** (destructive `#b91c1c`). The destructive action is **never** the default focus.
4. On confirm, the server calls the sanctioned writer (`tools.agree.write.retire` — flip in place, never delete) and the UI transitions to Post-retire. **The referrer files are never modified by this tool** — the copy states this explicitly.
5. Cancel returns to the prior state with no write.

### Accessibility (system-native, minimal but real)
- Every interactive element has a visible 2px accent focus ring (`:focus-visible`), keyboard-operable (Tab order = list → detail → actions).
- Confirm dialog uses native `<dialog>` (focus trap + `Esc` for free); focus lands on `Cancel`; returns focus to the trigger on close.
- Status is conveyed by **text** (badges say "ACTIVE"/"RETIRED"), never color-only — retired also carries strikethrough + muted color so it survives color-blindness/grayscale.
- Buttons are real `<button>`s with text labels; no icon-only controls.
