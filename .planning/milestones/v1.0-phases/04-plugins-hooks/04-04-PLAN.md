## Phase Goal

**As a** developer or coding agent working in this polyglot harness, **I want to** have the Phase 1-3 contract, §4.3-4.6 boundary, and permission rules enforced by non-bypassable runtime hooks, **so that** a violation is blocked at write/commit time instead of relying on advisory prose.

<objective>
Build the HOOK-01 format-on-write gate: a PostToolUse(Write|Edit) hook that enforces LF / no-BOM / InvariantCulture on every edit (language-neutral byte fix), then runs `ruff format` for `.py` files and `dotnet format` for `.cs` files (dotnet-gated, skip-gracefully when absent). This is the format half of Phase 4 success criterion 3.

Purpose: make encoding hygiene automatic and non-negotiable at write time. The formatter mutates via a SUBPROCESS (not a Claude Write) so it does not re-enter the PostToolUse hook (Open Q3 re-entry loop); it is idempotent so a second pass is a no-op. The byte-level LF/BOM rule reuses the §4.3-4.6 convention (no divergent normalizer); the .NET formatter is an optional gated add-on that must never fail the gate for an env limitation (Pitfall 3, D-05).
Output: a tested fixer proving BOM+CRLF -> LF/no-BOM, idempotency, and graceful dotnet-absent skip.
</objective>

| Boundary | Description |
|----------|-------------|

| hook -> external formatter subprocess | ruff / dotnet-format spawned as a child process (must be argv, shell=False; dotnet gated). |
