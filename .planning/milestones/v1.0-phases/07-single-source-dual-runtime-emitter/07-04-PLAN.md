## Phase Goal

**As a** harness maintainer, **I want to** compile the single runtime-neutral `harness/` source into both runtime artifact trees, merging (not overwriting) shared human/GSD files, **so that** the runtimes stay byte-faithful to one source without clobbering the GSD workflow the repo runs on. This plan delivers the first of the two risky merge surfaces: the Markdown managed-block splice.

<objective>
Deliver `merge.py`'s Markdown regime (Regime B-md): an idempotent HTML-comment managed-block splice into the shared, human/GSD-owned root `AGENTS.md` and `CLAUDE.md` — never a full overwrite. This is one of the two riskiest surfaces flagged for isolation (the other, `settings.json`, is Plan 05).

Purpose: `AGENTS.md` and `CLAUDE.md` carry GSD-managed sections (the Project block, nearest-wins rules) and human prose from Phases 2/5. The emitter must own ONLY a fenced managed block and preserve everything else verbatim, or it breaks the repo's operating rules. Idempotency is what makes the CI re-emit-diff gate green on these shared files.

Output: `merge.py` marker splice, its heavy idempotency test, and the merged `AGENTS.md`/`CLAUDE.md` committed.
</objective>
