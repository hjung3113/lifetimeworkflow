Delete the skill-registry self-gate in its entirety — the tool package
(`tools/skill_registry/`, 611 LOC), its declaration file (`harness/skills/registry.lock`), its
in-suite mirror test (`tools/harness_lint/tests/test_skill_registry_lock.py`), the CI job

on any diff against the committed lock. Phase 40 must land before Phase 41's first skill deletion
per ADR-0012 (`docs/adr/0012-ci-and-merge-as-decision-authority.md:96-97`) and milestone ordering
rule (1). This is a pure-deletion phase: nothing is created, no replacement gate is added (D-02).

Output: one atomic commit (D-01) containing every deletion below, `uv.lock` refreshed, all nine
D-08 verification commands (V-1..V-9) green.

**Commit-shape note (structural, not aspirational — read this before executing).** This revision
collapses what were previously Task 2 (delete package/lock/mirror-test/CI-edit) and Task 3
(refresh `uv.lock` + run the verification suite) into a single Task 2 below. Reason: any executor
following a standard "commit after each `type=auto` task" protocol would otherwise produce a first
commit that deletes `tools/skill_registry/` while `uv.lock` still names
`source = { virtual = "tools/skill_registry" }` for that now-deleted directory — a broken
intermediate tree, which is exactly what D-01 forbids ("every intermediate split is a broken
tree"). Merging the deletion and the lock-refresh-and-verify step into one task means the
default per-task-commit behavior of ANY executor (commit-per-task or manual) naturally yields
exactly one commit containing the whole teardown, with no dependency on the executor honoring a
negative instruction ("stage but do not commit"). Task 1 is read-only/verification-only and
stages nothing, so whether or not an executor attempts a commit after it, there is nothing staged
and the step is a no-op either way.
