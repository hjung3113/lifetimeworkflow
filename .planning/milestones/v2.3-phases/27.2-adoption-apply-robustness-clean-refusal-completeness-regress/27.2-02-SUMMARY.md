# Phase 27.2 Plan 02: WR-07 Concurrency-Control Regression Detector Summary

Rewrote the WR-01 concurrency test to assert observed mutual exclusion of the marker-merge
critical section, and added a committed negative control that patches `fcntl.flock` to a no-op and
requires the positive test's own assertion helper to raise — closing WR-07 with zero production
source changes.

## What was built

`tools/adoption_apply/tests/test_atomic_apply.py`, WR-01/WR-07 section only:

- `_observe_marker_merge_concurrency(tmp_path, monkeypatch, *, barrier=None)` — monkeypatches
  `apply.splice_managed_block` (the function `_apply_marker_merge` calls between the read and the
  atomic write, INSIDE the flock-held critical section) with a wrapper that counts occupancy under
  a `threading.Lock`, records `("enter"|"exit", tag)` events, dwells, and delegates to the real
  function so merge semantics are unchanged. Runs two racers on a `ThreadPoolExecutor(max_workers=2)`
  and returns `(max_concurrent, events, final_text)`.
- `_assert_mutual_exclusion(max_concurrent, events)` — the one pass/fail judgement:
  `max_concurrent == 1` plus strict enter/exit alternation with no interleave.
- `test_concurrent_marker_merge_does_not_lose_writes` (rewritten) — runs the observer with no
  barrier, calls `_assert_mutual_exclusion`, keeps the byte-consistency assertions. The
  `lock_path.is_file()` assertion is **deleted**, with a section comment naming WR-07 so it is not
  restored.
- `test_concurrency_control_removal_is_detected` (new, D-06) — `monkeypatch.setattr(apply.fcntl,
  "flock", lambda *args, **kwargs: None)`, runs the SAME observer with a `threading.Barrier(2)` so
  the overlap is forced rather than sampled, then requires `_assert_mutual_exclusion` to raise
  inside `pytest.raises(AssertionError)`.
- `test_marker_merge_acquires_exclusive_flock` (new) — `MagicMock(wraps=fcntl.flock)` spy; asserts
  it was called and that a call's second positional argument was `fcntl.LOCK_EX`.

Every patch goes through the `monkeypatch` fixture (T-27.2-09) — `apply.fcntl` IS the stdlib module
object, so process-wide restoration at teardown is mandatory. Zero new package installs (T-27.2-SC):
stdlib `fcntl`/`threading`/`time` only.

## RED evidence (SC-4)

The removal-detection record is produced by a committed, repeatable, CI-running test rather than a
one-off local mutation. Captured from
`uv run pytest tools/adoption_apply/tests/test_atomic_apply.py -k "concurren or flock" -q -s`:

```
WR-07 negative control observed max_concurrent=2
WR-07 negative control AssertionError: marker-merge critical section was entered concurrently: max_concurrent=2 (expected 1); events=[('enter', '## Block A'), ('enter', '## Block B'), ('exit', '## Block A'), ('exit', '## Block B')]
assert 2 == 1
```

That `AssertionError` text is verbatim what `test_concurrent_marker_merge_does_not_lose_writes`
would emit if the `fcntl.flock(lock.fileno(), fcntl.LOCK_EX)` line were deleted from
`_apply_marker_merge` — it is the same helper, the same assertion, the same message.

- **Observed `max_concurrent` under no-op `flock`:** `2` (both racers inside the critical section
  simultaneously; the event stream shows `enter A, enter B, exit A, exit B` — a genuine interleave).
- **Observed `max_concurrent` with the real `flock`:** `1`, event stream strictly alternating.
- **Final dwell:** `_DWELL_SECONDS = 0.2` — unchanged from the first attempt; no lengthening was
  needed because the 20x gate was clean on the first pass.
- **Barrier timeout:** `_BARRIER_TIMEOUT_SECONDS = 5.0`. Zero barrier timeouts across all runs.
- **Stability (Task 2):** 20/20 consecutive green, `FLAKES=0`, on the
  `-k "concurren or flock"` selection — which covers BOTH the positive test and the negative
  control (4 tests per run). No assertion was weakened at any point.
