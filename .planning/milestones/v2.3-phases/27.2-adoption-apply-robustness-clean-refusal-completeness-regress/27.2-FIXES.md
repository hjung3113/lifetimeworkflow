### CR-01 — `check_valid` raised on a non-UTF-8 `approval.json` · `8b13df5`

Two rows added to `CORRUPT_APPROVAL_CASES` before any source change. The table's callable rows may
now yield raw bytes as well as a perturbed document, so an encoding row stays derived from the
real promoted approval rather than a hand-written literal.

RED, pre-fix:

```
FAILED test_check_valid_never_raises_on_corrupt_approval[invalid_utf8]
E   UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc3 in position 16: invalid continuation byte
    /.../lib/python3.11/json/__init__.py:341: UnicodeDecodeError

FAILED test_check_valid_never_raises_on_corrupt_approval[valid_document_utf16]
E   AssertionError: valid_document_utf16
E   assert True is False
```

The first escapes because `UnicodeDecodeError` subclasses `UnicodeError` → `ValueError`: neither
`JSONDecodeError` nor `OSError`. It lands at the un-`try`'d `cli.py:148`, so `adopt apply` emitted
a traceback instead of the documented exit 4.

The second is the silent-encoding-sniffing path the review flagged in passing: `json.loads(bytes)`
runs `json.detect_encoding` and accepts a BOM'd UTF-16 document, so an approval in a non-UTF-8
encoding validated as **current** — which §4.3 byte hygiene does not sanction.

Fix: decode explicitly as UTF-8 before parsing; name `UnicodeDecodeError` in the catch tuple; drop
the redundant `FileNotFoundError` (an `OSError` subclass).

### WR-01 — the root-equality guard was dead under the test table · `8b2ba74`

Added `symlink_to_root` → `selflink` (an `os.symlink` at the target root) — the only spelling that
actually reaches the branch, since `.`, `./` and `` are all intercepted by the earlier structural
last-segment check. Every row in `DIRECTORY_SHAPED_DESTINATIONS` now carries an `expected_guard`
fragment, so a row cannot drift onto a different check and still pass.

Mutation evidence — `if target_path == Path(target_root).resolve():` → `if False:`:

```
FAILED test_refuse_unsafe_destination_rejects_directory_shaped[symlink_to_root]
E   assert 'target root itself' in "'selflink' resolves to an existing directory — refusing the write."
```

Without the branch the symlink falls through to the `is_dir()` check and is refused as the wrong
class of problem — invisible to the old assertion, which only checked that the destination was
quoted. The branch is now regression-detected rather than annotated as defense-in-depth.

### WR-02 — a destination whose ancestor chain is an existing FILE · `e2b2350`

RED, pre-fix (three tests, all added first):

```
FAILED test_refuse_unsafe_destination_rejects_non_directory_ancestor[parent_is_file]
FAILED test_refuse_unsafe_destination_rejects_non_directory_ancestor[grandparent_is_file]
E   Failed: DID NOT RAISE <class 'tools.adoption_apply.apply.PathEscapeError'>

FAILED test_apply_disposition_refuses_non_directory_ancestor
E   FileExistsError: [Errno 17] File exists: '/.../AGENTS.md'
```

Fixed per D-01 at the choke point, not in the except tuple: walk `target_path.parents` down to the
target root and refuse any existing non-directory ancestor, before any filesystem write. The
end-to-end test spies `os.open`/`os.link`/`os.replace` to prove zero writes and that the existing
marker file is left byte-identical. `FileExistsError`/`NotADirectoryError` were added to the CLI
tuple as backstop-only defense in depth, with a comment recording that the guard now makes them
unreachable by construction.

### WR-03 / WR-04 — the "Never raises" promise and the over-broad `try` · `76e7a57`

**WR-04** is a scope fix, not a membership fix: the mutation table shows `JSONDecodeError`,
`KeyError` and `TypeError` are each load-bearing, so all three are kept and the `try` is shrunk to
the parse plus the three subscript reads (now read eagerly into one tuple).
`_recompute_draft_hash` keeps its own narrow `except OSError` — WR-02's original coverage.

RED, pre-fix:

```
FAILED test_check_valid_lets_a_task_control_defect_surface
E   Failed: DID NOT RAISE <class 'KeyError'>
```

i.e. a `show()` returning a state dict without `"revision"` — a genuine CAS-layer defect — was
swallowed and reported to the operator as "this approval is stale, re-promote".

Post-fix mutation re-check (drop `KeyError` from the tuple): `3 failed` —
`missing_draft_hash`, `missing_task_revision`, `missing_git_ref`. Every member remains
load-bearing after the narrowing.

**WR-03** — the docstring now bounds the promise to the approval *document* and names
`AdoptionApprovalRefused` and `TaskControlError` as deliberately un-absorbed environment faults.
`test_check_valid_propagates_an_environment_fault` pins that behaviour; it is a characterization
test (green pre-fix) that documents what the old flat "Never raises" denied.

### AD-03 — the no-content-leak guarantee had no test · `72bd301`

Every corruption row now matches stderr against the exact one-line shape (prefix + batch id + path
+ exception class name), which forbids payload bytes structurally rather than by searching for
individual substrings. Rows that return `False` by simple inequality print nothing and are exempt.

Mutation evidence — appending `: {exc}` to the diagnostic (the smallest realistic leak) turns
**9 of the 12** corruption rows RED (`json_string`, `json_number`, `missing_draft_hash`,
`missing_task_revision`, `missing_git_ref`, …).

The deviation AD-03 also names — D-04 specified "a structured invalid result with a distinct
reason string", the implementation returns a bare `bool` and prints — is hereby **documented as an
accepted deviation**: `check_valid` was always `-> bool`, so D-04's premise was factually wrong;
changing the return shape now would be a caller-visible contract change for no operator benefit,
and `cli.py` already emits the exit-4 refusal message. The diagnostic channel is the `print`, and
it is now controlled by a test.

### AD-04 / AD-05 — docstring accuracy in `apply_manifest` · `19e487f`

Docstring-only; no behaviour change.

- **AD-04** — the docstring claimed `CollisionError` is an "integrity fault" that propagates,
  while the CLI flattens it to the same exit 1 as a routine path refusal. The distinction is now
  recorded as in-process-only.
- **AD-05** — partial application is documented as deliberate (re-run-after-fix, guarded by
  `atomic_create`'s collision check) rather than changed. Bucketing `PathEscapeError` alongside
  `ConstitutionRefusal` was considered and rejected: it would silently downgrade the genuine
  escape/symlink cases to a per-record outcome.

## Residuals (carried forward, deliberately not fixed)

- **AD-01** — `barrier.wait(timeout=...)` raises `BrokenBarrierError`, so on a loaded CI box the
  negative control's failure mode is an unrelated-looking error rather than a legible "the control
  is no longer detected". Not fixed: rewriting a threading/timing test is not trivially safe, and
  the review itself classes this as a legibility concern, not a correctness one
  (`test_marker_merge_acquires_exclusive_flock` is the timing-independent backstop).
- **AD-02** — `monkeypatch.setattr(apply.fcntl, "flock", ...)` mutates the singleton stdlib
  module, disabling locking process-wide for the duration. Safe today (pytest is single-threaded
  here); becomes a hazard under `pytest-xdist --dist loadfile`. The fix (a module-local `_flock`
  indirection) changes the production locking path and is not trivially safe for a review-fix
  pass.
- **Pre-existing lint** — `ruff check tools/adoption_apply/cli.py` reports `I001` (unsorted import
  block). Verified byte-identical at base commit `dd3383b`; predates this phase and is already
  recorded in `27.2-01-SUMMARY.md`. `ruff check --ignore I001` and `ruff format --check` are both
  clean across `tools/adoption_apply` (23 files).
- Everything already listed as carried-forward in `27.2-01-SUMMARY.md` (27.1 WR-08 TOCTOU, IN-02
  advisory-flock-over-NFS, `manifest.schema.json` runtime-only tightening, `secret_scan.py`
  hardcoded pattern list) remains open and untouched.
