**New test 1 — SC-1 red→green proof (name must contain `ci_yml` per VALIDATION.md's `-k ci_yml`
filter).** Pattern: call `scan._secret_pattern()` directly against the real repo's own
`.github/workflows/ci.yml` content, asserting no match under the NEW pattern, and (for red→green
proof) asserting the OLD pattern DOES match. Model on the existing red/green pairing style already
used in this same file at `test_derived_marker_does_not_false_positive_on_ordinary_prose` /
`test_derived_marker_still_catches_real_generated_headers` (lines 44-80) — same "prove both
directions" structure, applied here to old-vs-new pattern instead of ordinary-prose-vs-real-marker:
```python
def test_ci_yml_false_positive_closed(repo_root: Path) -> None:
    """SC-1: this repo's own .github/workflows/ci.yml no longer classifies as secret-content."""
    ci_yml = repo_root / ".github" / "workflows" / "ci.yml"
    text = ci_yml.read_text(encoding="utf-8")
    old_pattern = re.compile(
        r"(?:api[_-]?key|secret|password|token)\s*[:=]\s*[^\s]+", re.IGNORECASE
    )
    assert old_pattern.search(text), "red check: old pattern must match (proves this is the bug)"
    assert scan._secret_pattern().search(text) is None or "secret-content" not in {
        entry["excluded"]
        for entry in scan.build_inventory(repo_root)["excluded"]
        if entry["path"] == ".github/workflows/ci.yml"
    }
```
(Planner should prefer the `build_inventory(repo_root)` form for the literal SC-1 wording proof;
the direct `_secret_pattern().search(text)` form is the more surgical red-green unit check —
RESEARCH.md's Pitfall 4 recommends doing both this way.)

**New test 2 — SC-2 parametrized 7-case proof (must contain `secret_shape` per VALIDATION.md's
