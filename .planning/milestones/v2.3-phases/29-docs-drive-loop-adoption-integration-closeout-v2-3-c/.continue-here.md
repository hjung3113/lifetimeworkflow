## The thing to carry forward

The repo's recurring defect showed up in a new shape. Usually it is *a control ships GREEN while
bypassable*. Here it was *a control was never built while four documents said it was*:
`docs/adr/0001-walking-skeleton-golden-core.md:48` declares a four-member constitution plane, the
Phase-4 stack enforced three, and `docs/glossary.md` was agent-writable for two weeks.

The tell was that the **documents were right and the code was wrong** — the opposite of the usual
direction. That is why two Claude audits (including this session's) nearly repaired it *backwards*,
by deleting the true sentence from `.memory/README.md`. Both cited ADR-0010, which was
`Status: proposed`, over ADR-0001, which was `accepted`.

**Check an ADR's status field before citing it as authority.** Accepted beats proposed. An external
audit (codex sol, medium) caught the inversion; the human ratification gate caught an agent's
reasoning, not a typo.

Related correction now written into three surfaces: constitution ownership controls **who may
edit**, a doc-review binding controls **when a human owes a review**. They are orthogonal —
`contract-graph-adr-0009` already pairs a `docs/adr/**` target the same way, and that counterexample
was in the same registry, already read, when the wrong recommendation was made.

## Three process lessons, all cheap to repeat

1. **Delegation.** Parallel extraction agents were slow, so I read the artifacts by grep and
   committed. That direct read was wrong in three places; the late delegate caught all three, and
   every error made a phase look **greener** than it was. Grep summaries of PLAN files miss
   `<task type="checkpoint:human-verify">` declarations. Read task-type declarations directly, or
   wait.
2. **Trust a plan's ordering even when its reason is unstated.** terra ordered A→B→C→ADR→ledger. The
   payoff only appeared at the end: repointing a binding **before** the first ledger exists skips
   the amber cycle entirely, because `first_seen-unratified` compares against the previous
   *committed* ledger and there was none. `lifecycle-eval-shadow-metrics` came out FRESH, not amber.
3. **`git commit`**: `-m` goes **before** `--`, or git reads the message as a pathspec. I hit this
   myself and then handed the user the broken form.
