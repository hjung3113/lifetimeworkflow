# Plan 37-01 — LANE-03: Capability Registry + Allowlist + Capability-Neutral Routing

**Requirement:** LANE-03 (TCP-F03) — route by declared capability, not by hardcoded persona name,
with an allowlist that something actually refuses.

**Goal (goal-backward):** a task packet whose discipline record routes to an agent outside the
declared capability's allowlist must be unable to leave its phase. If I cannot produce a single
command that shows that refusal, and a mutation that shows it flipping to green, the plan failed.

## Design in one paragraph

`harness/capabilities.toml` declares the capability vocabulary: id → the **allowlist** of personas
that may serve it, plus an optional `read_only` obligation. `harness/disciplines.toml` gains an
optional `capability` key — the declaration says *what kind of agent* it needs, never a name. A
discipline record names the `agent` that carried the work out (per **seat** for a panel). The
existing `validate_record` grows one defect class; the existing refusal in
`tools/task_control/manager.py:440` and `phase_gate.py:93` does the rest, unchanged.

## Tasks

### T1 — `tools/capability/` package (pyproject in the SAME commit)

- `tools/capability/pyproject.toml` — copy `tools/discipline/pyproject.toml`; name
  `harness-capability`; **no** dependencies beyond stdlib (`tomllib`).
- `tools/capability/__init__.py`, `tools/capability/registry.py`:
  - `CapabilityError(ValueError)` — malformed registry only, never an ordinary refusal.
  - `@dataclass(frozen=True) Capability(id, description, providers: tuple[str, ...], read_only: bool)`.
  - `DEFAULT_REGISTRY = REPO_ROOT / "harness" / "capabilities.toml"`.
  - `load_capabilities(path=DEFAULT_REGISTRY) -> dict[str, Capability]` — fail-closed: `version == 1`,
    non-empty `[capability]` table, closed key set
    (`description`, `providers`, `read_only`), `providers` a non-empty list of unique non-empty
    strings, `read_only` a bool. Shape only; no repository access (agent existence is the lint's job,
    mirroring how `load_declarations` does not stat a SKILL.md).
  - `providers_for(capability_id, *, registry=None) -> tuple[str, ...]` — raises on unknown id.
  - `route_defects(capability_id, agent, *, registry=None) -> list[str]` — the pure refusal
    function: `[]` when allowed; one message naming the capability, the agent and the allowlist
    otherwise. Unknown capability and unknown/absent agent are distinct messages.
- `tools/capability/__main__.py` — CLI. `python -m tools.capability list` prints
  `<id>\t<providers>`; `python -m tools.capability route <capability> <agent>` exits **0** when
  allowed, **3** when refused (the repo's established human-gate/refusal exit code), **2** on a
  malformed registry. The refusal message is the demonstration artifact.
- `tools/capability/tests/conftest.py` — copy `tools/lifecycle_eval/tests/conftest.py` verbatim,
  fixing the parents index. **Verify with `uv run pytest tools/capability` ALONE.**
- `tools/capability/tests/test_registry.py` — shape validation (each fail-closed branch), the
  allow/refuse decision, and the CLI exit codes.

### T2 — `harness/capabilities.toml`

Seed the vocabulary. Every `caps.EXPECTED_PERSONAS` member must appear in at least one `providers`
list (T4 gate):

| capability | providers | read_only | why |
|---|---|---|---|
| `adversarial-review` | `code-reviewer`, `explorer` | **true** | the seat that judges a change must not be able to edit it |
| `implementation` | `python-engineer` | false | the agent that writes the change |
| `reconnaissance` | `explorer` | true | locate/map, no writes |
| `orchestration` | `orchestrator` | false | decompose + route |
| `derived-maintenance` | `curator` | false | regenerates the derived plane only |

Header comment states the plane (runtime-neutral harness DATA, not a contract), the consumers, and
**why the allowlist is per-capability and not per-lane** (the monotone-superset argument).

### T3 — wire the capability into the discipline mechanism

- `harness/disciplines.toml`: add `capability` to all five declarations —
  `adversarial-review-panel` → `adversarial-review`; the other four → `implementation`. Extend the
  header field list.
- `tools/discipline/check.py`:
  - `Declaration` gains `capability: str | None = None`; add `"capability"` to `_DECLARATION_KEYS`
    (NOT to `_REQUIRED_DECLARATION_KEYS` — D-06 keeps it optional by design).
  - `load_declarations` validates it is a non-empty string **and a declared capability id**, raising
    `DisciplineError` otherwise. Load the registry once per call, not per declaration.
  - `validate_record`: when `declaration.capability` is set —
    - panel discipline: every review must carry `agent`; each `agent` outside the allowlist is a
      defect naming the seat.
    - non-panel: the record must carry `agent`; outside the allowlist is a defect.
    - a missing `agent` is its own defect message ("declaration declares capability X but the record
      names no agent"), so the failure is diagnosable, not just red.
  - Import `tools.capability.registry` lazily inside the functions if a module-level import would
    create a cycle; it does not — `capability` depends on nothing.
- `tools/discipline/record.schema.json`: add `"agent": {"type": "string", "minLength": 1}` at the
  root AND inside `panel.reviews.items` (both have `additionalProperties: false`).
- `tools/discipline/pyproject.toml`: no new dependency (workspace members import by path).
- `tools/discipline/tests/test_discipline.py`: add cases — allowed agent passes; out-of-allowlist
  agent defects; absent agent defects; a declaration with no capability is unaffected.

### T4 — `tools/harness_lint/tests/test_capability_wiring.py`

Bidirectional, each direction with a MUTATION PROOF operating on a **copy**:

1. every `providers` entry is a real `harness/agents/<name>.md` **and** a `caps.EXPECTED_PERSONAS`
   member;
2. every `EXPECTED_PERSONAS` member provides ≥1 capability (a persona nothing can route to is dead);
3. every `read_only = true` capability's providers satisfy `caps.is_read_only(frontmatter)` — parse
   the authored agent frontmatter, reusing whatever loader `test_agents.py` already uses;
4. every `capability` named by `harness/disciplines.toml` is declared;
5. MUTATION: point a declaration at an undeclared capability → `load_declarations` raises;
6. MUTATION: add a write-capable provider to a `read_only` capability → gate (3) fails;
7. MUTATION: point a provider at a non-existent agent → gate (1) fails.

### T5 — capability-neutral routing in the authored surface

- `harness/agents/orchestrator.md` — the routing procedure gains a capability step: resolve the
  **capability** the work needs, then pick a provider from `harness/capabilities.toml`. The persona
  table stays as the *current* resolution of that registry, explicitly labelled as derived from it,
  so the doc stops being the allowlist.
- `harness/skills/adversarial-review-panel/SKILL.md` — a seat is a declared capability
  (`adversarial-review`) filled by an allowlisted provider, and the seat record carries `agent`.
  **Keep the strings `fan-out-synthesize` and `explorer`** — `test_discipline_wiring.py` asserts both.
- The four other discipline skills: one line each, naming the capability their record must route to.
- `harness/commands/discipline.md` — mention that the report names the owed capability.
- **Re-emit** (`uv run python -m tools.harness_emit`) and commit both runtime trees; porcelain empty.

  will start failing. Expected and correct — update the fixtures in the same commit and say so in
  the SUMMARY (`tools/lifecycle_eval` fixtures are the likely site).
- **`EXPECTED_SKILLS` / command counters** do not move — no skill or command is added or removed.
  If that changes, `caps.py` and `tools/harness_emit/tests/test_coexist.py` move in the SAME commit.
- **Docs bindings.** `tools/task_control/*` and the harness surface are bound sources; run
  `tools.docs_guard` after and route per ADR-0010 — bounded target edit, ledger row **drafted**.
