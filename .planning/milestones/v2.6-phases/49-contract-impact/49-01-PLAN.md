<objective>
Add `tools/contract_graph/impact.py` — a pure, injectable-parameter reporter that answers "what does
changing this contract reach?" by composing three already-shipped engines: `query.py`'s
`direct`/`reverse`/`transitive` over `compile_graph()`'s adjacency, `harness_config.loader`'s
`effective_relationships()`/`effective_packages()`, and `ownership.py`'s `owning_package()`. This is
the module `/impact` (Plan 02) will call. It closes MONO-08's traversal-reuse requirement in
isolation from the command-surface/route-wiring work (MONO-09), which is Plan 02's concern.

Purpose: give the `contract-change` route (and any future caller) one composed, deterministic,
clean-refusing answer instead of the five-call inline one-liner it uses today — without creating a
second graph-traversal engine, which REQUIREMENTS.md and CONTEXT.md both forbid.

Output: `tools/contract_graph/impact.py` (new module in the existing `tools/contract_graph` package)
and `tools/contract_graph/tests/test_impact.py` (new test file), both on synthetic fixtures because
`compile_graph()` on the live core config returns `{"relationships": [], "adjacency": {},
"diagnostics": []}` — every one of this checkout's 6 real contracts hits clean-refusal today, so the
live tree cannot exercise the resolved/traversal code paths at all.
</objective>

```python
def direct(graph: dict, node: str) -> dict:
    """{"ids": sorted[dependents], "paths": [[node, dep], ...]}. Isolated node -> {"ids": [], "paths": []}, never KeyError."""

def reverse(graph: dict, node: str) -> dict:
    """{"ids": sorted[predecessors], "paths": [[node, pred], ...]}."""

```
