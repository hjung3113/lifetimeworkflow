def detect_manifests(included: list[dict]) -> list[dict]:
    """One manifestRecord per recognized manifest file present in included."""
    records: list[dict] = []
    for entry in sorted(included, key=lambda item: item["path"]):
        name = PurePosixPath(entry["path"]).name
        kind = _MANIFEST_KIND_BY_NAME.get(name)
        if kind is None and name.endswith(".csproj"):
            kind = "*.csproj"
        if kind is None:
            continue
        records.append({"path": entry["path"], "kind": kind,
                         "classification": "observed", "evidence": _evidence([entry])})
    return records

    - Each returned dict has `"name"` (str) and `"kind"` (`"runtime"` or `"dev"`); path-based
      entries (see below) additionally carry `"path"` (the raw, unresolved reference string as

    - `pyproject.toml` (`_dependencies_from_pyproject`): parse with `tomllib.loads(text)`.
      Runtime: each string in `data["project"]["dependencies"]` (default `[]`), with the bare
      package name split off before any version specifier / marker (split on the first character
      in `<>=!~;[ ` — reuse `re.split(r"[<>=!~\[; ]", dep, maxsplit=1)[0].strip()`). Dev: each
      string in `data["dependency-groups"]["dev"]` (default `[]`, PEP 735 — this repo's own root
      `pyproject.toml:12-19` uses exactly this table), same name-splitting. No `"path"` key on
      these entries (name-resolved, not path-resolved) — resolution happens by matching the bare
      name against a known package id in Plan 47-02.
    - `package.json` (`_dependencies_from_package_json`): parse with `json.loads(text)`. Runtime:
      every key of `data.get("dependencies", {})`. Dev: every key of
      `data.get("devDependencies", {})`. Values (version specifiers) are ignored. No `"path"` key.
    - `*.csproj` (`_dependencies_from_csproj`): parse with `xml.etree.ElementTree.fromstring(text)`.
      Every `<ProjectReference Include="...">` element (`.//ProjectReference`, no namespace on this
      element in this repo's `.csproj` files) yields one entry: `"name"` = the raw `Include`
      attribute value verbatim (e.g. `"../../libs/dotnet/Normalize/Normalize.csproj"`), `"kind"` =
      `"runtime"` (a `.csproj` carries no dev/runtime distinction), `"path"` = the same raw
      `Include` value (this is a relative-path reference to another `.csproj`, always path-based
      — never name-resolved).
    - `go.mod` (`_dependencies_from_go_mod`): line-based parsing (no stdlib Go-module reader
      exists). Recognize both forms: a `require (\n\t<module> <version>\n...)` block and a
      single-line `require <module> <version>`. Each recognized module path yields `"name"` = the
      module path string, `"kind"` = `"runtime"` (go.mod has no dev-dependency concept). No
      `"path"` key (module paths are name-resolved against another package's declared module
      path, mirroring pyproject/package.json).
    - `Cargo.toml` (`_dependencies_from_cargo_toml`): parse with `tomllib.loads(text)`.
      Deliberately scoped to PATH dependencies only (per CONTEXT.md decision — Cargo.toml parser
      = "path dependencies"): for each `[dependencies]` table entry (kind `"runtime"`) and each
      `[dev-dependencies]` table entry (kind `"dev"`) whose value is itself a table containing a
      `"path"` key, emit `"name"` = the dependency's table key (the crate name), `"kind"` =
      runtime/dev, `"path"` = the declared path string verbatim. A plain string version spec or a
      table with no `"path"` key (registry/git dependency) is SKIPPED entirely — never returned
