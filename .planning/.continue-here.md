- [ ] CONSTRAINT: **A check that cannot fail.** Six distinct instances across phases 40–46, every one
  passing while the thing it guarded was absent: `RETIRED_SIGNATURES[0]` reading only entry 0;
  `test_output_is_deterministic` asserting `[] == []`; `test_pipeline_config` looping over an emptied

  deleted; `CONSTITUTION_GLOBS` keeping `golden/**` after the baselines moved (all 7 matched
  nothing); and three Phase-46 predicates passing on prose elsewhere in the same file.
  **Structural mitigation required:** whenever a plan adds or edits an assertion, mutation-test it —
  break the thing it guards and confirm it REDs *before* committing. Scope predicates to the section
  they govern (`awk '/^## Section/,0' | grep -q`), never whole-file, and count per-block: whole-file
  counts are routinely off by one because a shared preamble or template block contributes an extra.
  The v2.3 form of this constraint was "a control ships GREEN while being bypassable" — same defect,
  and the same fix.

- [ ] CONSTRAINT: **Never forge a human-ratification token.** `GOLDEN_APPROVE_HUMAN` must never be
  set by an agent, and `HARNESS_DEV_BYPASS` must not be used to edit the plane a gate protects —
  Phase 45 stopped and deferred the two-line `docs/glossary.md` edit for exactly this reason, because
  bypassing a gate to tidy what it guards makes the gate decorative. If you find a path around a
  gate, that is a **reportable defect, never a shortcut**.
  *(The v2.3 constraint about `docs/.docs-review-ledger.toml` is now obsolete — Phase 41 deleted the
  ledger, `ledger_guard`, and the whole docs-review plane.)*

**Do not proceed until both boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Checks that cannot fail | See the blocking constraint above. Six instances, phases 40–46. | blocking | Mutation-test every new or edited assertion. Section-scope predicates; count per-block. |
| Live-tree-rendering artifacts repaired late | A committed test/snapshot/frozenset/count that renders the live tree, invalidated by a change, named by no plan. Phases 43–45 produced twenty-plus instances. `pytest --collect-only` sees none — they are runtime assertions. | blocking | Repair each in the **same commit** as the change that invalidates it. Enumerate every count literal, frozenset, `.ambr` and hardcoded path list before planning. Direction-agnostic: Phase 46 *added* a command and hit the identical set. |
| Reading-based plan verification | Three reading passes in Phase 43 each declared the defect set closed and were each wrong; a replay then falsified a per-commit greenness claim all three had accepted. | blocking | Verify plans by **replaying the planned commits in a scratch clone**, running the suite after each. ~¼ the token cost for strictly better coverage. Verify `tools.__path__` and `sys.prefix` resolve into the scratch tree first, or the sim silently reads the real repo. |
| Interaction defects between individually-correct changes | Phase 44's `GOLDEN_DIR`: the `golden/` fold and the `parents[2]→[3]` anchor fix were each right; combined in one commit they resolved to a deleted directory. Phase 46's `orchestrator.md:49`: KEEP the intake section, DELETE the routing table — leaving the deployed persona's first routing step pointing at nothing, commit green. | blocking | Invisible to review and to a green suite; only a commit replay surfaces them. When a plan both KEEPS and DELETES inside one file, check every KEEP for a pointer into the DELETE. |
| `git commit` mechanics | `-m` after `--` makes git read the message as a pathspec and abort — **recorded in the v2.3 handoff and hit twice again this session**. Separately `git commit -- <pathspec>` rejects paths git does not yet know, so the milestone's only additive commit aborted outright until an explicit `git add` was added. | advisory | Message BEFORE `--`. For any NEW file, run a targeted `git add <path>` first. Only `git add -A` / `git add .` / `git commit -a` are forbidden. |
| Sweeping by token instead of by meaning | Three categories legitimately name deleted surface: the relocated package that *implements* a gate; history notes naming a retired artifact **in order to record its retirement** (`caps.py:124,134`, `test_coexist.py:56`, `test_commands.py:42`); and append-only ADR text. | advisory | Stale means *a live file describing a control, path, or command that no longer exists*.
