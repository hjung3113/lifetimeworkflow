# BLOCKING CONSTRAINTS — Read Before Anything Else

> Not suggestions. Each was discovered through actual failure, most of them more than once.
> Acknowledge each explicitly before proceeding.

- [ ] CONSTRAINT: **A control ships GREEN while being bypassable.** This is the defect of the whole
  milestone. It recurred in Phase 26, 27, 27.1, inside 27.2's own fix, and again in Phase 28 as
  three Criticals. Every time, the cause was the same: every test fixture used the one input
  spelling the control already handled. What caught it was never the suite passing — it was
  adversarial **mutation testing**: delete the control, see whether anything reds.
  **Structural mitigation required:** for any control-shaped change, author the adversarial-input
  table FIRST, run the new test against pre-fix code, and confirm it fails FOR THE STATED REASON.
  The gate is "would this test fail if the fix were reverted?", not "does the suite pass?"

- [ ] CONSTRAINT: **Do not author `docs/.docs-review-ledger.toml`.** An agent writing a new binding
  together with its own `reviewed-no-change` row IS the attack Phases 28 and 29 exist to close — an
  honest seed row and a self-blessed row are byte-identical, and only a human commit separates them.
  Three layers deny it: `tools/hooks/ledger_guard.py` (PreToolUse, honours NEITHER
  `GOLDEN_APPROVE_HUMAN` NOR `HARNESS_DEV_BYPASS`), `refuse_unsafe_destination` →
  `ReviewLedgerRefusal`, and the `first_seen-unratified` history test. If you find a path around
  any of them, that is a **reportable defect, never a shortcut**.

**Do not proceed until both boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Happy-path-only fixtures | A guard tested only with the spelling it already handles. Produced 27.1's CR-01/CR-02, 27.2's WR-05/06/07, and 28's CR-01/02/03. Suite stays green; control is bypassable. | blocking | Adversarial table authored before the fix; RED step run and confirmed failing for the documented reason. Reviewer mutation-tests each control and reports which survive deletion. |
| An ADR asserting a control that does not exist | Phase 28's CR-02: ADR-0010 claimed a three-layer enforcement model, but layer 1 had no enforcer at all — no hook consumed `path_deny_globs`, and the test "guarding" it only asserted the data matched itself. | blocking | A test that asserts data against itself is not a control. Assert IDENTITY against the source of truth (`x is contract_guard.CONSTITUTION_GLOBS`), and assert the WIRING, so deleting the hook group reds. |
| Inverted `!` gate accepting a collection error | `! uv run pytest ...` exits 0 on `ModuleNotFoundError`, which masquerades as RED. Bit 28-02 directly. | blocking | Run RED selections PLAIN and read the full output. Passes reported alongside failures prove collection succeeded. Never pipe pytest into `head`/`tail` — the pipeline reports the last command's status. |
| `git commit` publishing the whole shared index | With concurrent executors, `git commit` publishes everything staged, not what the preceding `git add` named. Swept 28-01's entire constitution-plane set into a sibling's `test(28-09)` commit. | blocking | `git commit -- <pathspec>` every time, with `git diff --cached --name-only` inspected immediately before. Never `git add -A`, `git add .`, or `git commit -a`. |
| Green under one invocation, red under the one that matters | `tools/lifecycle_eval` imported fine under the full suite (a sibling conftest had already inserted the repo root) but errored under the isolated CI command. | advisory | Run the exact command CI runs, not an equivalent. |
| Repairing on the way past a closeout | Tempting during the audit; refused per T-29-21 — a closeout that repairs as it goes reports a state that never existed. | advisory | Record the defect in the audit, repair it as its own task with its own evidence. |
