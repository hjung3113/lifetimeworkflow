<objective>
Demote `[[components]]` from the source of truth to an override slot layered over the Plan 47-02
derived package facts, via a new `effective_packages(cfg=None, facts=None)` in
`tools/harness_config/loader.py` — mirroring `effective_relationships()`'s "lower/derive, union
with declared, field-level layering" shape, with ONE deliberate divergence: a `[[components]]`
entry with no matching derived package id must NOT raise (`effective_relationships` raises on
mismatch; MONO-03 explicitly forbids that here).

Purpose: MONO-03's hard requirement is that BOTH live configs — the core generic default
(`harness/project.toml`, components `source`/`sink`) and the instance overlay (the example's own
`project.toml`, components `parser`/`converter`/`scheduler`/`collector`) — keep loading with
**zero edits**, even though none of those 6 component ids match any of the 23 real
manifest-derived package ids in this checkout today. That "no match → declared-only, no error"
behavior is the plan's central proof, not an edge case. **GEN-04 note:** the instance overlay's
config file lives under `examples/` — a literal `examples/` path string is forbidden in any file
under `tools/`, `harness/`, `libs/` (hard constraint, no exceptions taken). So the instance-config
proof is placed as its OWN test file under `examples/log-parser/tests/` (outside the root pytest
`testpaths`, mirroring `test_pipeline_topology.py`'s exact placement/precedent), never inside
`tools/harness_lint/tests/`.
Output: `effective_packages()` in `loader.py`, its lazy re-export in `__init__.py`, unit tests, the
core-config `harness_lint` gate, and the instance-config example-leg gate.
</objective>
