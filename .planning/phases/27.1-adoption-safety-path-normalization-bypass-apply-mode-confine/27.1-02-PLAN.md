<objective>
Close CR-03 from `27-REVIEW.md`: nothing in `cli.py`'s `apply` subcommand ever consults
`approval.check_valid`, so a batch can be applied whether or not a human ever promoted it — directly
contradicting `brownfield-adoption/SKILL.md`'s documented claim that promotion gates the apply.
Wire `check_valid` into `_cmd_apply` as a hard precondition (mirroring `promote`'s existing exit-3
refusal idiom with a new, distinct exit code 4 per RESEARCH's Assumption A2). In the same module,
close WR-02 (`check_valid` raising instead of returning `False` on a missing draft artifact) and
WR-04 (`_cmd_apply` never re-validates `manifest.json` against its schema before use, unlike
`_cmd_draft`).

Purpose: the human-ratification gate (`ADOPT-06`) that Plan 27-04 spent an entire plan building is
currently decorative on the apply path — an agent or bare CLI/CI caller can skip `promote` entirely.
Purpose (WR-04): a schema-invalid or tampered `manifest.json` currently surfaces as an unhandled
`KeyError` traceback rather than the clean refusal every other `cli.py` failure mode already gives.
Output: `_cmd_apply` refuses (exit 4) without a valid, exactly-matching approval; refuses (exit 1) on
a schema-invalid manifest; `check_valid` never raises.
</objective>
