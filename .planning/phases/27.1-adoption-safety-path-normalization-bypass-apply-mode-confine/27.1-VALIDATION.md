# Phase 27.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Source: `27.1-RESEARCH.md` § Validation Architecture.

**Standing rule for this phase:** every fix MUST be preceded by a data-based case that **fails against
the shipped Phase 27 code** (SC-5). Phase 27's controls shipped green because every fixture used the
one destination spelling that worked. A test that cannot fail when the control regresses is not
coverage — that is the entire reason this phase exists.

## Sampling Rate

- **After every task commit:** `uv run pytest tools/adoption_apply -q`
- **After every plan wave:** `uv run pytest -q` + `uv run python -m tools.contract_drift.drift`
- **Phase gate:** full suite green · contract-drift clean · **both** `.memory/derived/contracts-index.md` **and** `tools/memory_regen/tests/__snapshots__/test_contracts_index.ambr` current (see Pitfall below) · emit clean
- **Max feedback latency:** 10 seconds (quick), 90 seconds (full)

> **Inherited pitfall — do not repeat.** Phase 27's plan 27-02 regenerated the derived plane but did
> not update the `memory_regen` snapshot, leaving a red gate that the next plan inherited and
> deferred. The two artifacts must move in the same commit.
