# Phase 27.1 Plan 02: CLI-boundary approval gate + schema revalidation + hostile-destination catch Summary

**`_cmd_apply` now hard-refuses an unpromoted or stale-approval batch (exit 4), re-validates `manifest.json` against its schema before use, and cleanly catches `PathEscapeError`/`SymlinkRefusal` instead of leaking a raw traceback.**

## Performance

- **Duration:** 35 min
- **Tasks:** 2 (RED test suite, GREEN implementation)
- **Files modified:** 4

## Accomplishments

- Closed CR-03: `approval.check_valid` is now a hard precondition of `_cmd_apply`, called first, before any manifest read or write — `brownfield-adoption/SKILL.md`'s claim that promotion gates the apply is now literally true.
- Closed WR-02: `check_valid` catches `FileNotFoundError`/`OSError` from `_recompute_draft_hash` and returns `False` — no partial credit, no crash, on an incomplete batch directory.
- Closed WR-04: `_cmd_apply` re-validates `manifest.json` against `manifest.schema.json` via the existing `_validate` helper (already used by `_cmd_draft`) before dispatching to `apply_manifest`.
- Closed the plan-checker BLOCKER: the except tuple around `apply_manifest` now also catches `apply_module.PathEscapeError` and `apply_module.SymlinkRefusal` (both introduced by 27.1-01), converting a hostile-destination manifest into the same clean exit-1 refusal every other `apply_manifest` fault already gets.
- Added a required `--repo-root` flag to the `apply` subparser, mirroring `promote`'s own flag (D-02).
