# Phase 27.1: Adoption Safety — Research

**Researched:** 2026-07-21
**Domain:** Path confinement / traversal defense, symlink safety, human-ratification gate wiring, JSON Schema path-shape constraints (Python 3.11, stdlib `pathlib`/`os`)
**Confidence:** HIGH — every empirical claim below was executed live in this session (Python 3.9.6 dev shell; target runtime `requires-python = ">=3.11"` per `tools/adoption_apply/pyproject.toml` — the `pathlib`/`os` behaviors tested are stable across 3.9–3.13, no 3.11-specific divergence found)

## Summary

All three CR findings are real, reproduced live, and share one root cause: `tools/adoption_apply/apply.py` has two independent path-safety primitives (`refuse_if_constitution`, `refuse_if_outside_root`) but only one of them (`refuse_if_outside_root`) is resolved-path-based, and neither is wired into the actual `apply` write path for every write. The fix is not "write a smarter glob" — it is **make `apply_disposition` funnel every destination through one confinement-then-classification choke point**, using `Path.resolve(strict=False)` + `Path.is_relative_to()` (both already used correctly by `refuse_if_outside_root`), before either check runs, and call that choke point from `apply_disposition` (not just from `cli.py`'s draft-only call site).

Case-insensitivity is a genuine, un-punted design decision, not a bug: `Path.resolve()` on this repo's own case-insensitive-APFS dev machine does **not** canonicalize case — verified live, `CONTRACTS/x.json`'s `.resolve()` still returns `CONTRACTS/x.json` — so resolving the path does nothing for the case problem. The only safe, platform-independent choice is to run the constitution-glob comparison case-insensitively **always** (`.lower()` on both the resolved relative path and the globs), never conditioned on `sys.platform`. This is a deliberate over-refuse: on a case-sensitive filesystem (Linux CI) it will refuse a small number of destinations that are not actually dangerous there — that is the correct trade given the harm asymmetry (missing a real constitution write vs. refusing a benign one).

Symlinks were tested concretely: a symlink at a destination whose target lands inside `contracts/` is correctly resolved by `Path.resolve()` (it follows the symlink and lands the resolved path inside `contracts/`, which the confinement/classification logic then catches) — so **the fix does not need a new symlink-specific code path, only that the classification runs against the resolved path, not the raw string**. Separately, `_apply_marker_merge`'s *read* side (`target_path.read_text()`) will silently follow a symlink and merge constitution-plane content into a target file — verified live this does NOT corrupt the constitution-plane source (`os.replace` on a symlink destination replaces the symlink itself, not what it points to — also verified live) but IS a confidentiality-shaped bypass (constitution content gets read and spliced into a foreign target file). Recommend `os.open(..., os.O_NOFOLLOW)` (confirmed available and correctly refuses on this platform) at the marker-merge read site as defense in depth, flagged as new scope beyond the review's literal findings.

CR-03's fix is a one-line, well-precedented wiring: `_cmd_apply` must call `approval.check_valid(...)` before `apply_manifest`, refusing with a new exit code (4, since 3 is already `promote`'s refusal code) — mirroring `golden_runner/approve.py`'s exit-code idiom exactly, which this codebase already treats as the house style.

**Primary recommendation:** Introduce one new choke-point function in `apply.py` — call it `refuse_unsafe_destination(destination, target_root)` — that (1) rejects absolute paths and literal `..` segments structurally before any resolution, (2) resolves `target_root / destination` and confines it via the existing `refuse_if_outside_root` logic, (3) computes the target-root-relative resolved path and matches it case-insensitively against `CONSTITUTION_GLOBS`. Call this ONE function from `apply_disposition` before every branch, replacing the current bare `refuse_if_constitution(destination)` call. Wire `approval.check_valid` into `_cmd_apply` as a hard precondition. Add the `pattern` constraint to `manifest.schema.json`'s `destination`/`path` fields as a constitution-plane edit with the full ritual (hash rebaseline, drift check, derived regen — **both** `.memory/derived/contracts-index.md` AND `tools/memory_regen/tests/__snapshots__/test_contracts_index.ambr` must move together, human checkpoint).

### Alternatives Considered
| Instead of | Could Use | Tradeoff |
|------------|-----------|----------|
| Always-case-insensitive constitution-glob match | Platform-conditional (`sys.platform == "darwin"` → case-insensitive, else case-sensitive) | Rejected: the *code* runs the same regardless of platform, but the *filesystem underneath a given `target_root`* could be case-insensitive even on Linux (e.g., an exFAT/SMB-mounted target) — `sys.platform` tells you about the runtime host, not the target filesystem. ### Pattern 1: Adversarial-input parametrize table shared across every guard
**What:** One `pytest.mark.parametrize` list of hostile `destination` spellings (`"contracts/x.json"`, `"./contracts/x.json"`, `"a/../contracts/x.json"`, `"CONTRACTS/x.json"`, `"/etc/passwd"`, `"../../../../etc/passwd"`, a symlink fixture whose target lands in `contracts/`), applied identically to (a) `refuse_unsafe_destination` directly, and (b) `apply_disposition` end-to-end with a zero-write spy — so a future edit that reintroduces a bypass in EITHER layer fails loudly, not just the layer someone remembered to re-test.
**When to use:** Any place multiple call sites are each supposed to enforce the same invariant (exactly the CR-01/CR-02 shape: one correct function existed, but not every caller used it).
**Example:**
```python
# Source: pattern derived from tools/adoption_apply/tests/test_constitution_refusal.py's existing
# test_refuses_before_mutation (already the right IDIOM — spy on os.open/os.link/os.replace,
# assert zero calls) — this phase's job is to widen its @pytest.mark.parametrize destination list,
# not invent a new test shape.
HOSTILE_DESTINATIONS = [
    "contracts/widget.schema.json",       # literal — already caught pre-27.1
    "./contracts/widget.schema.json",     # leading ./ — CR-01
    "a/../contracts/widget.schema.json",  # .. traversal landing inside — CR-01
    "CONTRACTS/widget.schema.json",       # case-variant — CR-01 (case-insensitive FS)
    "/etc/passwd",                        # absolute — CR-02
    "../../../../etc/passwd",             # .. traversal escaping target_root — CR-02
    # symlink case constructed via a fixture, not a string literal — see Pitfall/Code Examples below
]

@pytest.mark.parametrize("destination", HOSTILE_DESTINATIONS)
def test_refuses_before_mutation(tmp_path, monkeypatch, destination):
    open_spy = MagicMock(wraps=os.open)
    link_spy = MagicMock(wraps=os.link)
    replace_spy = MagicMock(wraps=os.replace)
    monkeypatch.setattr(os, "open", open_spy)
    monkeypatch.setattr(os, "link", link_spy)
    monkeypatch.setattr(os, "replace", replace_spy)

    record = {"destination": destination, "disposition": "create"}
    with pytest.raises((apply.ConstitutionRefusal, apply.PathEscapeError)):
        apply.apply_disposition(record, tmp_path, payload=b"content")

    assert open_spy.call_count == 0
    assert link_spy.call_count == 0
    assert replace_spy.call_count == 0
```
Also assert the *legitimate* case explicitly (a destination that must still be ALLOWED, e.g. `"src/widget.py"`), so the fix doesn't over-refuse into a false-positive DoS on normal adoption traffic.

### Pattern 2: `fcntl.flock`-guarded read-modify-write, copied not imported
**What:** WR-01's fix — hold an exclusive lock across `_apply_marker_merge`'s read + merge + write, exactly mirroring `batch.py::update_status`.
**When to use:** Any read-modify-write against a shared target file where two `apply` invocations could race.
**Example:**

# here to a marker-merge TARGET file instead of a batch's own status.json.
def _apply_marker_merge(destination: str, target_path: Path, block_body: str = "") -> None:
    target_path = Path(target_path)
    lock_path = target_path.with_name(f".{target_path.name}.lock")
    lock_path.parent.mkdir(parents=True, exist_ok=True)
    with lock_path.open("a+b") as lock:
        fcntl.flock(lock.fileno(), fcntl.LOCK_EX)
        if destination.endswith(".json"):
            existing = json.loads(target_path.read_text("utf-8")) if target_path.is_file() else {}
            merged = merge_settings(existing)
            payload = (json.dumps(merged, indent=2, ensure_ascii=False) + "\n").encode("utf-8")
        else:
            existing_text = target_path.read_text("utf-8") if target_path.is_file() else ""
            merged_text = splice_managed_block(existing_text, block_body)
            payload = merged_text.encode("utf-8")
        _atomic_replace(target_path, payload)

### Anti-Patterns to Avoid
- **Standalone `re`/`fnmatch` re-compilation in a test to assert behavior:** 26.2-RESEARCH.md's Pitfall 2 applies here too — always call the real `apply.refuse_unsafe_destination`/`apply_disposition`, never a hand-rolled reproduction, when asserting a security property.
- **Fixing CR-01 by only lowercasing the raw destination string, without resolving `..`:** a `.lower()`-only fix defeats the case-variant bypass but NOT the `..`-traversal bypass — both must be closed by the SAME resolved-path pipeline, not two independent patches.
- **Trusting `os.path.normpath` alone for confinement:** it does not follow symlinks, so it cannot catch the SC-1 symlink case; it is a useful pre-check (reject literal `..` segments before hitting the filesystem) but not a substitute for `Path.resolve()` + `is_relative_to()`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Path confinement (is X inside root Y) | A new string-prefix or manual `os.path.commonpath` check | `Path.resolve()` + `Path.is_relative_to()` (or the existing `resolved_root not in resolved_path.parents` idiom in `refuse_if_outside_root`) | `refuse_if_outside_root` already gets this right — reuse it verbatim, don't reimplement |
| Constitution-plane glob matching | A second glob engine or regex-based matcher | `tools.harness_perms.resolve_path` + `tools.hooks.contract_guard.CONSTITUTION_GLOBS` (already the shared, audited data) | Two independently-drifting copies of "what counts as constitution plane" is exactly the kind of split this phase should not introduce |
| Approval/ratification refusal semantics | A new refusal exception type or exit code scheme | Mirror `tools/golden_runner/approve.py`'s exit-code idiom (`AdoptionApprovalRefused` → distinct nonzero exit) already used by `_cmd_promote` | House convention; `_cmd_apply` should look like `_cmd_promote`'s error handling, not invent a new shape |
| Read-modify-write locking | A new lock file scheme | `fcntl.flock` sidecar-lock idiom already in `batch.py::update_status` | Exact same race-condition shape (concurrent apply/mutation on a shared file), exact same fix already proven in this codebase |

**Key insight:** Every fix in this phase has a correct sibling implementation already living somewhere else in `tools/adoption_apply/` or `tools/task_control/` — the defect pattern across all of CR-01/CR-02/CR-03/WR-01 is "a correct control exists but isn't wired everywhere it needs to be," not "the correct control doesn't exist yet." Planning should therefore bias toward *wiring* tasks with adversarial-input regression tests, not toward *designing new* mechanisms.

## Common Pitfalls

### Pitfall 1: Fixing the glob but not the schema (or vice versa) leaves one layer unguarded
**What goes wrong:** WR-03 (schema pattern) and CR-01/CR-02 (runtime checks) look like duplicate work but are NOT — the schema catches a malformed manifest before draft-time validation even runs (defense in depth against a hand-edited or corrupted `manifest.json` between draft and apply, which WR-04 shows currently isn't re-validated at all).
**Why it happens:** Once the runtime checks are fixed, a planner might deprioritize the schema change as "redundant."
**How to avoid:** Do both. WR-04's re-validation-at-apply-time fix only matters if the schema itself constrains the shape (WR-03) — the two findings are causally linked, plan them together.
**Warning signs:** A plan that closes CR-01/CR-02 but marks WR-03/WR-04 "accepted, not needed" without an explicit rationale addressing the "manifest tampered with after drafting" threat the review names.

### Pitfall 2: Both derived-plane artifacts must move together on a constitution-plane edit (Phase 27's own regression)
**What goes wrong:** 27-02 regenerated `.memory/derived/contracts-index.md` but forgot `tools/memory_regen/tests/__snapshots__/test_contracts_index.ambr`, leaving a red gate the next plan inherited.
**Why it happens:** The `.ambr` snapshot is a *test fixture*, easy to forget it's coupled to the derived artifact it's asserting against, since it lives under `tests/__snapshots__/` not `.memory/derived/`.
**How to avoid:** After `python -m tools.memory_regen.contracts_index`, explicitly re-run `uv run pytest tools/memory_regen/tests/test_contracts_index.py` and, if it's red on a snapshot mismatch, either the snapshot needs `--snapshot-update` (if the new content is correct) or the generator has a bug — never leave it red and move on.
**Warning signs:** `git status` shows `.memory/derived/contracts-index.md` changed but `tools/memory_regen/tests/__snapshots__/test_contracts_index.ambr` unchanged, on a commit that touched a hashed contract.

### Pitfall 3: `Path.resolve()` does not fix case-insensitivity — don't assume it does
**What goes wrong:** A fix that resolves the path and then does a case-sensitive glob match will still miss `CONTRACTS/x.json` on this repo's own dev machine — verified live in this research session.
**Why it happens:** `resolve()`'s docs describe it as "making the path absolute, resolving any symlinks" — it's easy to assume this also normalizes case on a case-insensitive filesystem, but it does not; it preserves the casing given.
**How to avoid:** Explicitly lowercase both the resolved relative path and `CONSTITUTION_GLOBS` before the `fnmatchcase` call, as a deliberate, commented decision — not left implicit.
**Warning signs:** A test suite that only runs on a case-sensitive CI runner and never actually exercises the `CONTRACTS/x.json` case will pass green while the fix is still broken on the dev machine (and vice versa) — this is exactly why SC-1 requires a data-based case for it.

### Pitfall 4: `os.replace` on a symlink destination is SAFE for the write, but the read before it is NOT
**What goes wrong:** Assuming that because `os.replace()` correctly replaces a symlink (rather than following it) — verified live — there's no symlink risk in `_apply_marker_merge` at all. The READ (`target_path.read_text()` / `target_path.is_file()`) still follows the symlink and pulls in whatever it points to, including constitution-plane content, before merging and writing back.
**Why it happens:** Symlink-safety intuition usually focuses on the write step (the dangerous "TOCTOU overwrite" pattern); the read-side information disclosure is a different, less commonly discussed failure mode.
**How to avoid:** Either (a) call `refuse_unsafe_destination` early enough that a destination whose resolved path lands in `contracts/` is refused BEFORE `_apply_marker_merge` even opens it (this is already the fix's design — the resolved-path check happens before dispatch), which closes this by construction since a symlink *whose target* is in `contracts/` is exactly the SC-1 case; or (b) additionally harden the read with `O_NOFOLLOW` as defense in depth if the destination itself (not just its target) could be attacker-controlled between draft and apply.
**Warning signs:** A marker-merge target's `.resolve()` differs from its own un-resolved `Path` — this is the observable signal a symlink is present at that destination.

## Code Examples

### Verified live: `refuse_if_outside_root`'s existing pattern is already correct — reuse verbatim
```python
# Source: tools/adoption_apply/apply.py:87-99 (unchanged by this phase — reuse, don't reinvent)
def refuse_if_outside_root(path: str | Path, root: str | Path) -> None:
    resolved_root = Path(root).resolve()
    resolved_path = Path(path).resolve()
    if resolved_path != resolved_root and resolved_root not in resolved_path.parents:
        raise PathEscapeError(
            f"'{path}' resolves outside the confined root '{root}' — refusing the write."
        )
```

## Open Questions

1. **Should `refuse_if_constitution` (the current public name) be kept as a name, with its signature changed to require `target_root`, or should a genuinely new function name be introduced?**
   - What we know: Existing tests call `refuse_if_constitution("contracts/example.schema.json")` and `refuse_if_constitution("src/widget.py")` with no `target_root` argument.
   - What's unclear: Whether keeping the old name with a new required argument (breaking every existing caller) or introducing a new name (`refuse_unsafe_destination`) and deprecating the old one is preferred by the codebase's own convention.
   - Recommendation: Given `apply.py`'s history of the review calling out "the fix" as a signature change to `refuse_if_constitution` itself (see CR-01's fix snippet: `def refuse_if_constitution(destination: str, target_root: str | Path | None = None)`), the planner may choose to widen the EXISTING function's signature with an optional `target_root` param (backward compatible when `None`, only doing raw-string matching — but then that mode is exactly the current unsafe behavior). Cleaner: keep `refuse_if_constitution` as a raw internal helper only called AFTER resolution inside a new `refuse_unsafe_destination`, and fix the existing two tests to call the new function. This avoids ever calling the raw-string version directly from `apply_disposition` again.

2. **Does `_cmd_apply` need a new `--repo-root` CLI argument, and should it default to `_REPO_ROOT` or be required like `promote`'s?**
   - What we know: `promote` already has `--repo-root` as a required arg; `apply` currently has no such flag.
   - What's unclear: Whether `apply`'s repo-root should always equal the harness's own checkout root (`_REPO_ROOT`, a Python constant, no flag needed) or should be a caller-supplied flag matching `promote`'s for symmetry/testability.
   - Recommendation: Match `promote`'s existing convention (explicit `--repo-root` flag) for consistency and testability (tests can point it at a tmp git repo), rather than hardcoding `_REPO_ROOT` — but this is a naming/API surface decision for the plan to make explicitly.
