# Phase 27.1 Plan 01: Path Normalization / Apply-Mode Confinement Summary

**Introduced `refuse_unsafe_destination` as the single resolve-confine-classify choke point `apply_disposition` funnels every write through, closing CR-01 (constitution-plane bypass via `.`/`..`/case-variant/symlink spellings) and CR-02 (absolute-path confinement bypass), plus locked and symlink-safe `_apply_marker_merge` (WR-01 and a new symlink-read information-disclosure finding).**

## Accomplishments
- `refuse_unsafe_destination(destination, target_root) -> Path` is the new single choke point: structural absolute/`..`-segment reject before any filesystem call, then `Path.resolve(strict=False)`, then `refuse_if_outside_root` confinement, then a case-insensitive `CONSTITUTION_GLOBS` classification of the resolved, target-root-relative path — reusing `refuse_if_constitution`/`refuse_if_outside_root` unchanged (D-01).
- `apply_disposition` calls `refuse_unsafe_destination` as its first line and reuses the returned, already-resolved `target_path` for every branch, removing the redundant `Path(target_root) / destination` recomputation that silently discarded `target_root` for absolute destinations (the exact CR-02 mechanism).
- `_apply_marker_merge` now holds an `fcntl.flock`-guarded critical section across its entire read-merge-write sequence (mirroring `batch.py::update_status`'s sidecar-lock idiom verbatim), closing WR-01.
- New `_read_target_no_symlink`/`SymlinkRefusal`: the marker-merge read side now refuses (`os.O_NOFOLLOW`) to follow a symlink at the destination itself, closing a research-found information-disclosure risk (constitution-plane or other foreign content silently spliced into a target file through a symlinked marker-capable destination).
- Widened `test_constitution_refusal.py`/`test_atomic_apply.py` with a shared `HOSTILE_DESTINATIONS`/`PATH_ESCAPE_KINDS` adversarial table exercised against both `refuse_unsafe_destination` directly and the real `apply_disposition`/`apply_manifest` entry points — every new test failed against the pre-fix code for its own documented reason (missing function `AttributeError`, or a real write/lock-file absence proving the vulnerability), never a coincidence of an already-existing real-world path.
