<objective>
Teach the classification layer to tell "the harness moved" from "a human edited the target", and
give `/adopt` a durable place to remember what it wrote.

Two pieces, both pure-ish library code with no CLI wiring (Plan 03 wires them):
1. `destinations.py` — `DISPOSITION_ENUM` grows to 7, `disposition()` gains an `installed_sha`
   keyword and one new chain step between `preserve` and `conflict`, `build_manifest()` gains an
   `installed` keyword and copies those records into the manifest it emits.
2. `tools/adoption_apply/installed.py` — a small reader/writer for the TARGET-resident
   `.harness/adoption/installed.json`, schema-validated on BOTH read and write.

Purpose: SC-2 and SC-3 both reduce to one question — is the divergence at this destination something
adopt itself caused, or something the target's owner did? Exactly one stored hash answers it.

Output: the widened chain, the record module, and the paired positive/negative test coverage the
53-VALIDATION.md anti-vacuous contract requires.
</objective>

**The record shape** (contract landed by Plan 53-01, `contracts/harness/adoption/manifest.schema.json`):
`$defs.installedRecord` = object, `additionalProperties: false`, required
`["destination", "installed_sha256", "batch_id"]`. The optional top-level `installed` property is an
array of those records.

**The target-resident document** at `<target_root>/.harness/adoption/installed.json` is
`{"installed": [<installedRecord>, ...]}` — a one-key envelope, nothing else. It carries NO
timestamp and NO run counter: a `last_run_at` field would make SC-2's no-op unobservable by
construction (53-CONTEXT.md, locked).

**Validation reuse** — do not hand-roll a shape checker and do not create a second schema file.
Build the envelope schema in `installed.py` from the SHIPPED contract's own `$defs`:
`{"type": "object", "additionalProperties": false, "required": ["installed"], "properties": {"installed": {"type": "array", "items": {"$ref": "#/$defs/installedRecord"}}}, "$defs": <manifest_schema["$defs"]>}`
then validate with `jsonschema.Draft202012Validator`, exactly the validator
`tools/adoption_apply/cli.py:132-140` already uses. The record shape has ONE source of truth: the
contract file.

**Confinement**: `.harness/adoption/installed.json` is adopt's OWN bookkeeping, never a manifest
disposition row, so it does NOT route through `apply.refuse_unsafe_destination` (that choke point
classifies FOREIGN template destinations against the 7 rules). It gets its own single
`apply.refuse_if_outside_root(path, target_root)` call before any write — confinement is not
skipped, it is just the simpler one appropriate to a single fixed known path (53-RESEARCH.md

**`.harness/**` is not in `_CATEGORY_GLOBS`** today, so it is already absent from
`destination_catalog()` by construction. Add the same belt-and-suspenders structural skip
`_EXCLUDED_PREFIX` already gives `.workflow/tasks/**`, so a future careless glob cannot
reintroduce it.
