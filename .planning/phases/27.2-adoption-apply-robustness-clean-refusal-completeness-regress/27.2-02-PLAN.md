`tools/adoption_apply/apply.py` imports `fcntl` at module level and imports `merge_settings` and
`splice_managed_block` from `tools.harness_emit.merge` into its own namespace — so both the lock
primitive and the merge functions are reachable as module attributes (`apply.fcntl`,
`apply.splice_managed_block`, `apply.merge_settings`) and can be monkeypatched WITHOUT editing
`apply.py`.

`_apply_marker_merge(destination: str, target_path: Path, block_body: str = "") -> None`, the
critical section, in order:

    target_path = Path(target_path)
    lock_path = target_path.with_name(f".{target_path.name}.lock")
    lock_path.parent.mkdir(parents=True, exist_ok=True)
    with lock_path.open("a+b") as lock:
        fcntl.flock(lock.fileno(), fcntl.LOCK_EX)      # <-- the control under test
        if destination.endswith(".json"):
            existing_text = _read_target_no_symlink(target_path)
            existing = json.loads(existing_text) if existing_text is not None else {}
            merged = merge_settings(existing)
            payload = (json.dumps(merged, indent=2, ensure_ascii=False) + "\n").encode("utf-8")
        else:
            existing_text = _read_target_no_symlink(target_path)
            merged_text = splice_managed_block(existing_text or "", block_body)
            payload = merged_text.encode("utf-8")
        _atomic_replace(target_path, payload)

For a non-`.json` destination such as `"AGENTS.md"`, `splice_managed_block(existing_text, body)` is
called INSIDE the lock, between the read and the write — the ideal instrumentation point: a wrapper
that records entry, sleeps, records exit, and delegates to the real function makes any overlap of
two racers directly observable.

`fcntl.flock` is advisory and per-file-descriptor. Two threads in ONE process each opening the
sidecar path separately get separate descriptors, so `LOCK_EX` genuinely serializes them — the
existing test's `ThreadPoolExecutor(max_workers=2)` shape is sound; only its assertions are not.
(`fcntl.flock`'s NFS caveat is recorded as accepted residual risk in `27.1-REVIEW.md` IN-02 and is
explicitly not in this plan's scope.)

The current test to rewrite is `test_concurrent_marker_merge_does_not_lose_writes` at
`tools/adoption_apply/tests/test_atomic_apply.py:265-297`. The file already imports
`concurrent.futures`, `os`, `pytest`, `MagicMock`, and `from tools.adoption_apply import apply`.

Project rule (27.1 D-01): Phase 27's tests are append-only. `test_concurrent_marker_merge_does_not_

    barrier times out, that is a genuine failure to reproduce and must be investigated, never
