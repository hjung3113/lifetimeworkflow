### STOP-and-investigate: two rows passed on the first RED run

The plan required stopping if a row passed unexpectedly. On the first run,
`missing_task_revision` and `missing_git_ref` **passed** (5 failed / 5 passed). Cause: the table's
first draft wrote a synthetic well-formed document whose `draft_hash` was `"0"*64`, so
`check_valid`'s short-circuiting `and` returned `False` at the first comparison and never reached
the missing key — the row returned `False` for the wrong reason.

Fix (recorded, not silently applied to make the table match reality): the missing-key and
wrong-type rows now mutate the **real promoted approval document**, keeping every other axis
matching so each row isolates exactly its own key. Re-run: 7 failed / 3 passed as above, with
`missing_task_revision` and `missing_git_ref` now failing with their own `KeyError`.

## Changes

**`tools/adoption_apply/apply.py`** — `refuse_unsafe_destination` gains three refusals, all raising
the existing `PathEscapeError` (D-02):

1. structural, appended to the existing `segments` pre-check before any `resolve()`/filesystem
   call: `segments[-1] in ("", ".")` — the only check that sees `"a/"`, `"newdir/"`, `"a/b/."`;
2. `target_path == Path(target_root).resolve()` — the resolution-level backstop for any spelling
   collapsing onto the root;
3. `target_path.is_dir()` — an existing directory (false for a non-existent path, so D-03 holds).

Checks 2 and 3 sit before the `relative_to` classification, whose `"."` result matches no
constitution glob and is precisely what let `"."` through. Docstring updated with the new steps and
a WR-05 reference.

**`tools/adoption_apply/cli.py`** — `_cmd_apply`'s `except` tuple additionally names
`IsADirectoryError` and `apply_module.CollisionError`, with a comment stating it is a backstop, not
the guard. Same exit 1, same stderr format.

**`tools/adoption_apply/approval.py`** — `check_valid`'s guarded region widened to span
`json.loads` and the whole three-way comparison; `except` tuple extended with
`json.JSONDecodeError`, `KeyError`, `TypeError` alongside WR-02's `FileNotFoundError`/`OSError`,
each justified in the comment. The handler prints one stderr line naming the approval path and the
exception **class only** — never file content or the exception message body (T-27.2-03). `sys`
imported. Docstring now states the function never raises.

**Tests** — pure additions: `DIRECTORY_SHAPED_DESTINATIONS` (9 rows, grouped by class) plus a
parametrized refusal test, a negative control
(`test_refuse_unsafe_destination_still_allows_file_destinations`) and two end-to-end
`apply_disposition` rows with zero-write spies; `CORRUPT_APPROVAL_CASES` (10 rows) plus
`test_check_valid_never_raises_on_corrupt_approval`; and
`test_cli_apply_refuses_directory_shaped_destination` at the CLI boundary. No existing test was
weakened, renamed, or deleted (27.1 D-01).
