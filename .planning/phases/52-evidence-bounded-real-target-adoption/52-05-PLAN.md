## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness commands → external real repository | Commands operate on a repository outside this project; a wrong `--target` writes into someone's real working tree. |
| target repo content → harness scan/draft logic | Untrusted manifests, globs and scripts from a third-party monorepo. |
| evidence capture → phase record | Captures must be falsifiable; an edited capture destroys the record's value. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-52-15 | Tampering | `--target` pointing at the original `develop` checkout | high | mitigate | Every stage argv is fixed to the literal worktree path; the Task-3 automated verify matches `--target[[:space:]]+<original>($|[[:space:]])` against `argv.txt` and FAILS if it hits — the end-anchor is required because `--target <path>` is the final token, so a trailing-space pattern could never fire (W-6). The guard's own firing behavior is confirmed against a synthetic mis-targeted argv line before it is credited. The before/after original-checkout status comparison is the backstop. |
| T-52-16 | Tampering | `git worktree add` onto an existing path or a wrong SHA | high | mitigate | Provisioning refuses if the exact path already exists; the SHA is read from `target.develop.sha.txt` in the same task and re-asserted equal to the worktree's own `rev-parse HEAD`; detached state is verified via `symbolic-ref` failing. |
| T-52-17 | Tampering | Path traversal via the real target's `pnpm-workspace.yaml` globs | medium | mitigate | Mitigated in code by Plan 02 (absolute/`..` globs rejected, `_confined` re-validation); this plan additionally records the live workspace file verbatim so any hostile glob is visible in evidence. |
| T-52-18 | Repudiation | An edited or retried capture presented as a first-run result | medium | mitigate | Each stage runs once with fixed argv; all five sidecars are required; nonzero exits are recorded rather than retried; produced artifacts are copied, never hand-edited. |
| T-52-19 | Information Disclosure | Target secrets landing in committed evidence | medium | mitigate | The inventory's `excluded` records are structurally `{path,size,excluded}` with no hash or excerpt (D-10); only status/argv/exit captures and JSON artifacts are copied — never target file bodies other than the already-public `pnpm-workspace.yaml`. |
| T-52-SC | Tampering | npm/pip/cargo installs | low | accept | No installs; no `pnpm install` is run against the target (the harness never shells out to pnpm). |
