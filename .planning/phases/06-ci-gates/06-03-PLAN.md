<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR event → workflow `run:` shells | `pull_request` event fields (title, branch, author) are attacker-controllable; must NOT reach any `run:` shell. |
| third-party action refs → runner | Pinned actions execute with runner privileges; a compromised/typosquatted action is code-exec on CI. |
| GITHUB_TOKEN scope → repo | Default token scope can grant write; gate jobs need read-only. |
| repo config (project.toml) → matrix legs | Matrix values are repo-owned data (trusted), not event input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Tampering/Elevation | script injection via `${{ github.event.* }}` in `run:` | mitigate | Never interpolate event fields into shells; matrix legs derive only from repo-owned `harness/project.toml` via the loader. Reviewed at authoring (V1). |
| T-06-06 | Tampering | third-party/typosquatted actions | mitigate | Official publishers only (`actions/*`, `astral-sh/*`), version-pinned to VERIFIED tags v7.0.0 / v5.4.0 / v8.3.2; no `@main`/`@master` (V10). SHA-pin is a defensible optional upgrade (planner discretion, not required). |
| T-06-07 | Elevation | over-privileged GITHUB_TOKEN | mitigate | Top-level `permissions: { contents: read }`; gate jobs require no write scope (V14). |
| T-06-08 | Information Disclosure | secret leakage in logs | accept | Gate jobs require no secrets; `GOLDEN_APPROVE_HUMAN` is an in-session token, NOT a CI secret — CI gates on drift/golden directly and does not honor the bypass token. |
| T-06-09 | Denial (false-pass) | contract-check no-ops when no instance pairs | mitigate | Glob both `contracts/**` and `examples/**/contracts/**`; keep the visible `any==0 → SKIP` log so a no-op is not mistaken for a pass (Pitfall 5). |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No registry-package installs introduced; the three GitHub Actions are official-publisher, version-pinned, git-ls-remote-VERIFIED (RESEARCH §Package Legitimacy Audit — no [SLOP]/[SUS]). |
</threat_model>
