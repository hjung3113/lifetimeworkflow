<objective>
Enabler-2: add argparse `--contracts-dir` / `--baseline` to `tools/contract_drift/drift.py main()` and matching `--contracts-dir` / `--manifest` to `tools/contract_hash/hash.py main()`, so the Wave-2 CI `drift` job can gate BOTH the root manifest AND the example manifest (`examples/log-parser/contracts/.hashes/manifest.json`). The gate functions are ALREADY parameterized (`run_gate(contracts_dir, baseline_path)` at drift.py:133; `build_manifest(contracts_dir)` at hash.py:42) — but `write_manifest()` at hash.py:62-68 is NOT: it calls `build_manifest()` with NO arguments, so it always hashes the ROOT tree regardless of `--manifest`. This plan wires the argv wrappers AND threads `contracts_dir` through `write_manifest` so `--write --contracts-dir <example>` rebuilds the EXAMPLE baseline (not root-hash content written into the example manifest — a silent corruption).

Purpose: Without these flags CI cannot target the example contracts tree by verbatim tool reuse (D-01 — no re-implementation), so example-schema drift goes undetected (RESEARCH Pitfall 3); and without threading `contracts_dir` through `write_manifest`, a human rebaselining the example would corrupt it with root hashes. The change is a ~10-line CLI wrapper per file plus one signature thread; no gate/classification logic changes.
Output: two argparse-enabled CLIs (bare invocation unchanged), a tree-aware drift rebaseline message, `write_manifest` threading `contracts_dir`, and a Wave-0 test proving the drift flags route to the example manifest, honor pristine-pass / mutated-fail, and that `--write --contracts-dir <example>` writes example-rooted keys.
</objective>
