    Shape (implements the D-01 split; the field set is fixed by 28-RESEARCH.md Q1 and must not be
    extended):

    - root object, `additionalProperties: false`, optional `binding` property only.
    - `binding`: array of objects, each with `required: ["id", "sources", "target", "severity",
      "dispositions"]` and `additionalProperties: false`.
      - `id`: string, `pattern` `^[a-z0-9]+(-[a-z0-9]+)*$`, `minLength: 1`. (Uniqueness ACROSS rows
        is not expressible here — 28-03 enforces it.)
      - `sources`: array of strings, `items.minLength: 1`, `uniqueItems: true`. Do NOT set
        `minItems: 1` at the schema level: D-01/DOCSUP-01 requires the empty-selector rejection to be
        conditional on `severity == "required"`, and an unconditional `minItems` would make an
        `advisory` row with no sources unrepresentable rather than merely warned. Record that
        reasoning in the property `description`.
      - `target`: string, `minLength: 1`, exactly one human-authored target (not an array).
      - `severity`: `$ref` to `$defs/severity` — `enum: ["required", "advisory"]`.
      - `dispositions`: array, `minItems: 1`, `uniqueItems: true`, `items.$ref` to
        `$defs/disposition` — `enum: ["updated", "reviewed-no-change", "REVIEWED_STILL_CURRENT",
        "SUPERSEDING_ADR_REQUIRED"]`. All four spellings live in ONE enum; the ADR restriction
        (`docs/adr/**` targets get exactly the two upper-case values and never `updated`) is a
        cross-field policy that 28-03 enforces, because it depends on matching `target` against a
        glob. State that in the property `description` so a reader does not "tighten" the enum here.

    Forbidden in the schema, per DOCSUP-02 and CLAUDE.md: any timestamp/`date`/`updated_at` property,
    any reviewer/human-identity property, any prose-copy property, any model identifier anywhere in
    the file (including `$id`, `title`, and every `description`).
