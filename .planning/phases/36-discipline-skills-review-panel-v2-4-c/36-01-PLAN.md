pure checker that decides satisfied-vs-missing — without touching a single contract byte.

declared-where-a-gate-can-read-it. This plan builds the declaration and the decision function; plan
02 wires the refusal.

Output: a policy slot, a declaration file, and `tools/discipline/` with its tests. No lifecycle
behaviour changes yet.

| instance overlay -> core policy | an instance may raise requirements, never lower them |
| agent-written discipline record -> lifecycle gate | the record is the agent's own claim about method |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-01 | Elevation of Privilege | an overlay removes a discipline | mitigate | overlay offers only `required_disciplines_add`; the lower-lane sweep re-adds; `_validate_core_policy` rejects a non-superset |
| T-36-02 | Tampering | a discipline change slips past the packet's policy pin | mitigate | the key enters `_effective_policy`, so `policy_hashes.effective` moves |
| T-36-03 | Spoofing | a one-line JSON record "discharges" a discipline | mitigate | record must name the declared skill, be satisfied at/before the owing phase, and every `outputs` path must exist; panel findings must exist in `evidence.json` |

| T-36-05 | Denial of Service | a `tools/` member without a pyproject breaks every uv call repo-wide | mitigate | pyproject lands in the same commit; `workspace_check.py` is the bare-python3 escape hatch |
| T-36-SC | Tampering | dependency install | accept | no dependency added; `jsonschema` and `tomllib` are already workspace deps |
